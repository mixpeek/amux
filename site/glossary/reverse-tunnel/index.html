Reverse Tunnel

A technique for receiving inbound connections on a private machine without opening firewall ports — by having the private machine dial outbound to a public relay.

amux includes a built-in reverse tunnel — expose any localhost port at a stable HTTPS URL with one command: amux tunnel start 3000. No extra install, no ngrok subscription. View amux on GitHub ★

What is a reverse tunnel?

A reverse tunnel is a networking technique where a machine inside a private network — behind a firewall, NAT router, or corporate proxy — initiates an outbound connection to a public relay server. The relay then forwards inbound traffic back to the private machine through that established connection.

The result: the private machine gets a public-facing address (usually an HTTPS URL) without you opening any firewall port, configuring NAT rules, or exposing your IP. The client that reaches your service sees the relay's public address. The relay handles the NAT traversal invisibly.

Common uses: receiving webhooks from Stripe, GitHub, or Twilio during local development; sharing a development server with a client or remote team member; testing an IoT device's API from a cloud dashboard; exposing a local AI agent's HTTP API for external tools.

Reverse tunnel vs port forwarding

Both techniques make a private machine reachable from the internet, but they require different permissions:

TechniqueWho controls the network?Setup requiredWorks on corporate WiFi?
Port forwarding You (own the router/firewall) Router admin panel — map external port to internal IP No
Reverse tunnel The relay service (you just need outbound HTTPS) Run a client binary — no router access needed Yes, if outbound HTTPS is allowed

Port forwarding is simpler when you control the network (home lab, self-hosted server). A reverse tunnel is necessary everywhere else: corporate networks, cloud VMs behind NAT, shared hosting environments, or a laptop on public WiFi.

How a reverse tunnel works

  1. Your machine connects outbound to a relay server over HTTPS or SSH. No inbound port needed.
  2. The relay assigns a public URL — a subdomain like xyz.tunnel.example.com — mapped to your connection.
  3. When a request hits the relay's URL, the relay forwards it through the established outbound connection to your machine.
  4. Your local server handles the request as if the caller were on the same network, and the response travels back the same path.

The key invariant: your machine always dials out. The relay never initiates a connection to you. This is why reverse tunnels traverse NAT and firewalls that block inbound TCP while allowing outbound HTTPS.

amux tunnel

amux includes a reverse tunnel as a built-in feature — the only explicitly paid feature in the platform (gated on amux cloud). If you are already running amux to manage a fleet of AI coding agents, you do not need a separate tunnel install. 

amux tunnel start 3000        # expose localhost:3000
# → https://abc123.tunnel.amux.io (stable across restarts)

The tunnel URL is derived from your account token, so it stays consistent even if your machine restarts or the tunnel process crashes. The machine dials outbound; no inbound port is needed.

Common use within an amux fleet: an AI agent builds a local web app during an overnight run; you expose port 3000 so a client can preview the live development server from their phone — without deploying to a staging environment.

Security considerations

  • The URL is public but unguessable — derived from a token, not sequential. Anyone with the URL can reach your service. Do not tunnel sensitive data without adding application-layer authentication.
  • End-to-end encryption depends on the tool. ngrok and amux tunnel deliver HTTPS to the client; the relay-to-local segment runs over TLS on the control connection. Traffic is not end-to-end encrypted unless your local service also runs HTTPS.
  • For production use, Cloudflare Tunnel with access policies is the appropriate choice. Reverse tunnels for development and testing do not need the same security posture as production services.

Frequently asked questions

What is a reverse tunnel?

A technique where a machine inside a private network initiates an outbound connection to a public relay. The relay forwards inbound traffic back to the private machine through that connection. The private machine gets a public URL without opening any firewall ports.

How is a reverse tunnel different from port forwarding?

Port forwarding requires admin access to the router or firewall. A reverse tunnel requires only outbound HTTPS access — which most corporate networks, coffee shop WiFi, and cloud VMs allow. The tunneled machine dials out; the relay handles the inbound side.

What is a reverse tunnel used for?

Receiving webhooks from Stripe, GitHub, or Twilio during local development; sharing a dev server with a client or remote team; testing an IoT or AI agent API from an external dashboard; previewing a local app on a mobile device without deploying to staging.

What are the best open-source reverse tunnel tools?

ngrok (freemium, best ecosystem and inspection UI, custom domains on paid plan), localtunnel (free, no account, unstable URLs), Cloudflare Tunnel (free with Cloudflare account, production-grade access policies, custom domains), and amux tunnel (built-in for amux users, stable URL, no custom domains or TCP). Choose based on whether you need custom domains, URL stability, or zero configuration.

Does amux have a built-in reverse tunnel?

Yes. amux tunnel start 3000 publishes localhost:3000 at a stable HTTPS URL. The URL is token-derived and survives restarts. It is the only paid feature in amux — requires an amux cloud subscription. For custom domains, TCP tunneling, or an HTTP inspection UI, use ngrok or Cloudflare Tunnel instead.

Is a reverse tunneled service secure?

The URL is unguessable but not authenticated. Anyone who learns the URL can reach your service. For development and webhook testing this is generally acceptable. For production or sensitive data, add application-layer authentication or use Cloudflare Tunnel with access policies.
