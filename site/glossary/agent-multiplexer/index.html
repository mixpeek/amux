Agent Multiplexer

A platform that runs, monitors, and self-heals dozens of parallel AI coding agents from a single dashboard — without you managing each terminal separately.

Run an AI engineering team from one dashboard. amux is the open-source agent multiplexer for Claude Code, Codex, and Gemini CLI — self-healing, kanban board, phone control, MIT licensed. View amux on GitHub ★

Definition

An agent multiplexer manages the full lifecycle of multiple AI coding agent sessions running in parallel. It starts and stops sessions, monitors their health, restarts crashed agents, routes tasks from a shared board, tracks token usage, and surfaces status to a dashboard and mobile app — all without you logging into each terminal individually.

The term is borrowed from networking, where a multiplexer combines multiple signals over a single channel. In AI engineering, the "signals" are independent coding agents and the "channel" is a unified control plane.

How it works

Each agent session runs inside a tmux window managed by the multiplexer. The multiplexer tracks the session's output, infers its status (idle, working, waiting for input, crashed), and exposes that state via a REST API and web dashboard. A self-healing watchdog polls for stalled or crashed sessions and takes corrective action — restart, compact context, or alert the operator — without human involvement.

Tasks move from the board to agents via steering messages. When a session finishes, it marks the card done and the multiplexer picks the next queued task. The result: a team of AI agents working through a backlog overnight while you sleep.

Who uses agent multiplexers

Solo developers use them to parallelize their own backlog — assigning different features or bugs to different agents and checking progress from their phone. Engineering teams use them to share a fleet of agents across a project, with the kanban board as the coordination layer. CTOs and engineering managers use the dashboard to review what the fleet accomplished overnight.

The common thread: anyone who hits the ceiling of what a single AI coding session can do in a day.

Frequently asked questions

What is an agent multiplexer?

An agent multiplexer is a platform that runs, monitors, and coordinates multiple AI coding agents in parallel. It handles the lifecycle of each agent session — starting, stopping, restarting on failure, tracking status, and routing tasks — so you can operate dozens of Claude Code, Codex, or Gemini CLI workers from a single dashboard without managing each terminal separately.

How does an agent multiplexer differ from a task queue?

A task queue dispatches work items to workers and tracks completion. An agent multiplexer goes further: it manages persistent AI coding sessions (which hold context across tasks), self-heals when a session crashes, handles provider rate limits, compacts context overflows, and provides live status visibility via a dashboard and mobile app. Task queues are stateless by design; agent multiplexers are stateful by necessity.

Can one agent multiplexer run Claude Code, Codex, and Gemini CLI together?

Yes. amux treats each session as a terminal process, so any CLI-based AI coding agent runs inside it — Claude Code, Codex, Gemini CLI, Aider, Goose, or custom scripts. You can mix runtimes within a single fleet, assign different tasks to different agents based on their strengths, and monitor all of them from the same dashboard.

What happens when an agent crashes inside a multiplexer?

amux detects the crash via its watchdog and auto-restarts the session. If the failure was a context overflow, it triggers context compaction before restarting. If it was a provider rate limit, it waits and retries. The board card tied to that session is updated automatically so you can see what happened without checking each terminal pane.

Is there an open-source agent multiplexer?

Yes — amux is MIT-licensed and available at github.com/mixpeek/amux. It installs with a single script (./install.sh), requires only Python 3 and tmux, and runs entirely on your machine with no cloud dependency. The dashboard is accessible from any browser, including your phone as a PWA.

How many agents can one multiplexer handle?

amux users routinely run 20–50 concurrent agents on a laptop. The practical ceiling is your machine's memory and the number of open API connections your provider allows. The dashboard, board, and mobile app scale to hundreds of sessions without performance degradation — the bottleneck is always compute, not the multiplexer itself.
