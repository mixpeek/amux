// Coordination, end to end

Everything a fleet needs. Nothing it fights.

Every feature answers one question: what does a team of agents need that a single agent never did? Board, messages, schedules, groups, recovery. All in one Rust binary.

Atomic tasks

Claiming is compare-and-swap in SQLite, so two workers can never grab the same card. done requires evidence of what actually ran; verified requires a peer check.

Shared board

One kanban for the whole fleet. Dependencies via blocked_on; GET /api/board/ready returns only tasks whose dependencies cleared. How teams split work →

Loops

Autonomous loops pace themselves: the agent schedules its own next wakeup, drains the ready queue, and goes quiet when nothing needs it. Overnight runs without babysitting.

Schedules

Cron-style recurring prompts in plain words: daily at 9am, every 15m, weekly on Monday. Run history and audit trail included.

Groups

Workers organize into lanes: canvas, gtm, ops, customers. Same-group peers share memory, environment, and gates, so a lane behaves like a team instead of strangers.

Scope

Settings resolve card → worker → group → global. Set a gate, an env var, or a policy once at the right level and every worker below inherits it.

Worker awareness

Every worker sees the fleet: who is live, what they own, what they are doing right now. Peek into any peer's terminal before interrupting them.

@ each other

Workers message each other directly: delegate a task, request a review, report back. The server stamps the true origin on every message, so provenance is a fact, never a claim.

Steering

Type into any running session from the dashboard or your phone. Redirect mid-task, answer a blocked prompt, or drop context without stopping the run.

Model switching

Swap the model or provider on a running worker: Claude, Codex, Gemini, or a local Ollama model. Pick the brain per task, keep the worker and its context.

Message history

Every prompt, reply, and delivery is a ledger row with an id you can fetch later. When two accounts of an incident disagree, the history settles it.

Self-healing

The watchdog monitors context, auto-compacts, restarts crashed sessions, and replays the last message. Your team wakes up to finished work instead of dead terminals.

// Agent ↔ agent

Agents that coordinate without you.

Every session exposes a REST API. Agents discover peers, send tasks, peek terminals, and atomically claim board items, coordinating fleets of dozens with no human in the loop.

The full API reference lands in each agent's memory at startup, so plain-English orchestration just works: “ask worker-2 to add tests for the changes I just made.”

orchestration.sh 
# Send a task to another session (origin-stamped)
$ amux send worker-1 "implement /login and report back"

# Atomically claim a board item
$ curl -sk -X POST $AMUX_URL/api/board/PROJ-5/claim
{"ok":true,"claimed_by":"worker-2"}

# Only the tasks whose dependencies have cleared
$ curl -sk $AMUX_URL/api/board/ready

# Watch another session's live output
$ curl -sk $AMUX_URL/api/sessions/worker-1/peek

Frequently asked questions

amux is the open-source control plane for AI coding agents. It runs, coordinates, monitors, and recovers fleets of Claude Code, Codex CLI, and Gemini CLI sessions from one dashboard and a phone. Each agent is a named worker with its own repo, memory, and lane; a shared board with atomic task claiming keeps them from colliding. MIT licensed, single Rust binary.

amux sits above the agent runtimes rather than replacing them. Your agents stay vanilla CLI tools running in real terminal sessions; amux adds the layer they lack: a shared board with atomic claiming, origin-stamped messaging, schedules, loops, model switching, and self-healing recovery. When the underlying models improve, amux gets better with them. See the comparison pages for specifics.
