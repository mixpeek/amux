Security: what amux can and cannot access

Last updated: October 21, 2026

Short answer: self-hosted amux runs on your machine and sends us nothing. On amux Cloud you get your own dedicated server, and your code, prompts, files and model keys stay on it. The amux team can reach your server's hardware through our hosting provider, and our signup service reads an hourly usage report made only of counts and yes/no answers. Everything below says exactly what that means. To take everything with you, see You own your data.

We hold no security certifications and have had no third-party audit. The server code is public, so you can check every claim on this page in the amux repository.

Self-hosted amux

  • There is no amux account, and amux sends us no usage data, analytics or crash reports.
  • Your workers, board, notes and files stay in ~/.amux and your own folders.
  • The installer and updates download amux from GitHub. The agent CLIs you run (Claude Code, Codex, Gemini CLI) talk to their own providers under those providers' terms.
  • Optional features you turn on, such as calendar sync to your own S3 bucket, connect only where you point them.

amux Cloud: your own server

  • One server per customer. Each customer gets a dedicated Hetzner server at yourname.amux.io, in Falkenstein or Nuremberg (Germany) or Helsinki (Finland). It is shared with no one.
  • Your data stays on it. Workers, files, the board, notes, schedules and model keys (your Claude, ChatGPT or Gemini sign-in, or API keys) are stored on that server only. Code and prompts never pass through an amux service.
  • A sign-in gate in front of everything. Every request to the server goes through its sign-in gate first, over TLS with a Let's Encrypt certificate that renews automatically.
  • Three open ports. The firewall allows only 22 (SSH), 80 (certificate checks and the redirect to HTTPS) and 443 (HTTPS).
  • Public code, automatic updates. Each server updates itself hourly to the newest amux build that passed CI on the public repository's main branch, and rolls back if the new build does not come up healthy.

Signup and payment

  • Stripe Checkout takes the payment. We never see your card number.
  • Your password is hashed in your browser (scrypt) before it is sent. We never receive the password itself. The hash is kept in the Stripe order only until your server is built, then it is removed.
  • Your email address is stored with Stripe and on your server, where it is your sign-in name. We use it for the "server ready" email, billing links and account messages.

What the amux team can technically reach

Being specific about this matters more than sounding reassuring:

  • The hosting console. We hold the Hetzner account, so we can use Hetzner's console, rescue mode and snapshots for any Cloud server. That is the same level of access any hosting company has to the machines it rents out. We keep no SSH key on customer servers, and the server image is built with every SSH key removed.
  • Sign-in links. Our signup service holds a key that can create two-minute sign-in links for a server. It uses them for Sign in with Apple in the iOS app.
  • Usage counts. Since October 21, 2026 our signup service reads a usage report from each server once an hour, so we can spot customers stuck in setup and fix problems early. It contains counts and yes/no answers only: sign-ins and failed sign-ins, which model providers are connected, worker counts, tokens used today, the number of board cards and schedules, error counts, disk use and the amux version.
  • What the report never contains: messages, prompts, file or worker names, paths, email addresses, card titles, schedule commands, keys or tokens.

Backups and deletion

  • Hetzner takes a daily backup of each Cloud server and keeps the last seven.
  • Canceling keeps a final snapshot for 30 days, so re-subscribing with the same email restores your data. After 30 days the snapshot is deleted.
  • Deleting your account (from Settings on your server, or at amux.io/start/delete) ends the subscription and erases the server, its address, its backups and its snapshots right away, with no 30-day copy.

The amux.io website

amux.io uses PostHog analytics to see which pages lead people to star the repository or sign up. The privacy policy lists exactly what it records.

Reporting a vulnerability

Email info@mixpeek.com or open a GitHub security advisory, as the security policy describes. Please do not open a public issue for a vulnerability.
