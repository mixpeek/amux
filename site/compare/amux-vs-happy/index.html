What are amux and Happy?

amux is an open-source control plane for running an AI engineering team from a single dashboard or your phone. It launches, monitors and self-heals dozens of parallel Claude Code, Codex or Gemini CLI sessions, with a built-in kanban board, notes, CRM, email, browser automation and a scheduler. It is one Rust binary plus SQLite, open source under MIT + Commons Clause, and you can self-host it or rent an always-on server from amux Cloud.

Happy describes itself as an open-source harness for orchestrating coding agents: Claude, Codex and Grok in one desktop app, reusing the subscriptions you already pay for. Its desktop app (macOS, Windows, Linux) starts a background runtime called Happy Agent, and the iOS and Android apps reach the same sessions with end-to-end encryption. It is MIT licensed and has about 24k GitHub stars. The original happy CLI, which wraps Claude Code and Codex in your terminal, is now in maintenance mode.

Where do the agents run?

This is the biggest practical difference. Both tools can keep agents working while your laptop is closed, but only if they run on a machine that stays on.

With Happy, agents run on your own hardware. By default that is the computer running Happy Desktop. Its remote server guide shows how to install Happy Agent on a VPS or Mac mini so sessions continue while your laptop sleeps; you provide and maintain that machine.

With amux, you can do the same (install it on any Mac or Linux machine with curl -fsSL https://amux.io/install.sh | bash), or let amux Cloud provision a dedicated server at yourname.amux.io in about three minutes. You sign in with your own Claude, ChatGPT or Gemini account or an API key, and we run the box.

Which is better for running many agents at once?

amux is built around the team of agents. Each agent is a worker on the dashboard, work lives on a shared kanban board that agents claim tasks from, and a watchdog restarts any session that crashes or runs out of context. You can open the board on your phone, see which agent is stuck, answer its question and move on. That makes it a good fit for running a software project, or a small business, overnight.

Happy is built around the conversation. A session can hand bounded work to subagents on different models (its docs cap a tree at three levels deep and five agents), agents can message each other by ID, and any session can schedule a message for later. It is strong for one person directing a few deep tasks, and its model switching mid-conversation has no direct equivalent in amux.

Which is better from your phone?

Happy has native apps on both iOS and Android, and its phone sync is end-to-end encrypted, so its relay cannot read your code or messages. From the phone you can send messages and images, answer permission requests, switch model and start a session in any directory.

amux has a native iPhone and iPad app and a web app you can install on Android or any browser. The phone shows every agent at once with its live terminal, the task board, and controls to answer, approve, restart or reassign. Traffic goes over HTTPS straight to your own server rather than through a shared relay.

How much do amux and Happy cost?

Both are free to self-host, and both use your existing model subscriptions. Happy charges only for voice in its phone app beyond 20 free minutes per 30 days. amux is free to self-host; amux Cloud costs $39/mo for Solo (4 vCPU, 8 GB), $69/mo for Team (8 vCPU, 16 GB) and $129/mo for Max (16 vCPU, 32 GB). With Happy, any always-on server is your own cost and your own upkeep.

For freelancers and agencies running agents across several client repos, Cloud Team gives the agents enough memory to work on several projects in parallel without a machine on your desk.

When should you choose amux or Happy?

Choose Happy if

  • You want end-to-end encrypted phone access, or a native Android app.
  • You work on Windows or Linux desktops and want a native desktop app there.
  • You want a self-hosted team server where several people share sessions, each with their own sign-in.
  • You use Grok or Amazon Bedrock, or want to switch models mid-conversation.
  • You are happy to run your own always-on machine.

Choose amux if

  • You run more than a few agents and want them on one board, claiming tasks and recovering from crashes on their own.
  • You want Gemini CLI alongside Claude Code and Codex, each running as the vendor ships it.
  • You want CRM, email, browser automation and a scheduler in the same place as your agents, to run business tasks as well as code.
  • You want an always-on server without maintaining one: amux Cloud from $39/mo.

FAQ

Is amux a Happy Coder alternative?

Yes. Both let you run Claude Code and Codex and steer them from your phone. Happy (formerly Happy Coder) focuses on an encrypted desktop and phone app for your own sessions; amux focuses on running a team of agents on a shared task board, with an optional always-on amux Cloud server.

Do Happy and amux keep agents running when my laptop is closed?

Only if the agents run on a machine that stays on. Happy supports this by installing Happy Agent on a server or Mac mini you run. amux supports it the same way when self-hosted, or with amux Cloud, which gives you a dedicated always-on server at yourname.amux.io from $39/mo.

Does Happy support Gemini CLI?

Happy's providers are Claude, Codex, Grok and Amazon Bedrock. It can run Google Antigravity, OpenCode and other Agent Client Protocol agents as harnesses. amux runs Gemini CLI directly, alongside Claude Code, Codex, OpenCode and Ollama.

Is Happy free?

Yes. Happy is MIT licensed and free, and models run on your own Claude, Codex and Grok subscriptions. Its docs say voice in the phone app is the only paid feature. amux is also free to self-host; amux Cloud is the paid hosted option.

Which is more secure on the phone?

Happy encrypts phone traffic end to end, so its relay sees ciphertext only. amux has no relay: the phone connects over HTTPS directly to your own amux server, self-hosted or on amux Cloud. Both keep the agents and your code on a machine you control.
