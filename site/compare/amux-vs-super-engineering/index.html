amux vs super.engineering: Which Should Run Your Coding Agents?

super.engineering and amux both run Claude Code, Codex, Gemini and other coding agents in parallel, each on its own branch, and let you check on them from your phone. Compared on interface, running many agents, where agents run, phone access, license and price. Updated November 2026.

What are amux and super.engineering?

amux is a self-hosted control plane for running an AI engineering team from a single dashboard or your phone. It launches and monitors dozens of parallel Claude Code, Codex or Gemini CLI sessions, with a built-in kanban board, notes, CRM, email, browser automation and a scheduler. It is one Rust binary plus SQLite, source-available under MIT + Commons Clause, and you can self-host it or rent an always-on server from amux Cloud.

super.engineering, from Super Dot Engineering LLC, calls itself "the native agent control plane". It is a desktop app for macOS and Linux written in Rust on GPUI and drawn on the GPU, with no Electron or embedded web page. Every task gets its own git worktree and branch, with its own setup, run and test scripts and a real terminal, and the diff, checks and pull request sit beside the agent that made them. It works with 18 agent CLIs, including Claude, Codex, Gemini, Cursor, OpenCode, Copilot, Grok, Kiro, Qwen and Pi, signed in with your own accounts, and with GitHub, GitLab and Bitbucket. Its se command line lets agents create sessions, message each other and drive your browser tab. The app is free; it is funded by sponsors.

How do you drive each one?

super.engineering is a workspace on your desk. Each task opens as a worktree with terminals, chats, files, a diff and an embedded browser, and a picture-in-picture view lets you watch one agent while working in another. Because it is native, it stays fast with many sessions open. You can run the app's tests before you read a line of the diff, then create the pull request from the same window.

amux is organised around the team. Each agent is a named worker card on the dashboard with its live terminal, and work arrives as cards on a shared kanban board. The same view works in a browser, in the iPhone and iPad app, or in the Mac app, and nothing needs to be installed on the device you steer from.

Which is better for running many agents at once?

super.engineering's orchestration is led by an agent. You ask for an outcome, a lead agent splits it into roles (say API, UI and tests) across different providers, the roles message each other and keep shared state for decisions and checkpoints, and a fresh reviewer checks the integrated result. Every session stays visible in the app.

amux adds the layer that keeps a team of agents working without you: one board the agents claim tasks from atomically, so two never grab the same work; messages and @mentions between workers for handoffs and reviews; a scheduler for overnight and recurring runs; held delivery through a provider's usage limit, so a worker picks up again when the limit resets; and stall alerts when a worker stops making progress. Beside the agents sit a CRM, email with owner approval for outside sends, and browser automation with saved sign-ins.

Where do the agents run?

super.engineering runs agents as local processes on the machine running the app, signed in with your own accounts, and requests go straight to each provider. A remote SSH workspace keeps the checkout, terminals and agent sessions on another Linux or Mac host while the app runs on your Mac. Its iPhone app talks directly to the Mac, so the Mac must be awake with the app open; messages you send while it is unreachable wait on the phone until it is back.

amux self-hosted installs on any Mac or Linux machine with curl -fsSL https://amux.io/install.sh | bash, and keeps running when you close the browser tab. amux Cloud skips running a machine at all: it provisions a dedicated server at yourname.amux.io in about three minutes, 4 vCPU and 8 GB on Solo or 8 vCPU and 16 GB on Team. You sign in with your own Claude, ChatGPT or Gemini account or an API key, and we keep the box running and patched, so your agents keep working when your laptop sleeps and your phone reaches them from anywhere. You can export everything at any time (how).

How much do amux and super.engineering cost?

super.engineering is free. Its terms say sponsorship is the only thing it charges for, and sponsoring unlocks no features. You pay your model providers, and for any remote host you run agents on. Enterprise rollouts are scoped by email.

amux is free to self-host with every feature, and the code is on GitHub. amux Cloud costs $39/mo for Solo, $69/mo for Team and $129/mo for Max. The price covers the server itself, models are billed by your own provider plan, and the cost does not grow with the number of agents or teammates on the box.

For freelancers and agencies running agents across several client repos, Cloud Team is one always-on server every teammate can open, at $69 a month, with no Mac to leave awake and no VPS to set up and secure.

When should you choose amux or super.engineering?

Choose super.engineering if

  • You want a free, native desktop app that stays fast with many agents open.
  • Your work happens at your desk: a worktree per task with its own scripts, terminal, diff and pull request.
  • You want a lead agent to split work into roles across different providers.
  • You use an agent amux does not run, such as Cursor, Copilot, Grok, Kiro, Qwen or Pi.
  • You use GitLab or Bitbucket and start work from GitHub or Linear issues.

Choose amux if

  • You want agents that keep working while your laptop sleeps, without leaving a Mac awake.
  • You want agents that claim work from one shared board, message each other and hold through usage limits.
  • You want a scheduler, CRM, email and browser automation beside your agents.
  • You want a phone app on the App Store that reaches your agents from anywhere, plus Android through the web app.
  • You want an always-on server without running one: amux Cloud from $39/mo, or $69 for a team.

FAQ

Is amux a super.engineering alternative?

For running coding agents in parallel, yes. super.engineering is a free native app for macOS and Linux that runs Claude Code, Codex, Gemini, Cursor and 14 more agent CLIs, each task in its own git worktree, with review, pull requests and app-managed orchestration on your own machine. amux runs a team of agents on one shared task board with a scheduler, CRM, email and browser automation, and amux Cloud runs it on a dedicated always-on server we keep running.

Is super.engineering free?

Yes. Its terms say the software is free and that voluntary sponsorship is the only thing it charges for; sponsoring unlocks nothing. Enterprise setups are scoped by email. Its public GitHub repository holds bug reports and feature requests, and the app's source code is not published. amux is free to self-host with its source on GitHub, and amux Cloud costs $39 a month per server, or $69 for Team.

Can super.engineering keep agents running when my laptop is closed?

Agents run as local processes on the machine running the app, so they stop when that Mac sleeps. Its iPhone app connects directly to the Mac, which must be awake with the app open. A remote SSH workspace puts the checkout and agent sessions on another Linux or Mac host while the app runs on your Mac. amux runs on a server that stays on, self-hosted or as a dedicated amux Cloud server from $39 a month.

Does super.engineering have a phone app?

Yes, an iPhone app distributed through TestFlight. It pairs with one Mac and reaches it on the same Wi-Fi or over Tailscale, and shows projects, worktrees, chats and terminals running on that Mac. amux has a native iPhone and iPad app on the App Store and an installable web app, reaching your server from anywhere at yourname.amux.io on Cloud.

Is super.engineering the same as Superconductor?

No. super.engineering is made by Super Dot Engineering LLC and runs agents on your own machine. Superconductor (superconductor.com) is a hosted multiplayer workspace from Volition, Inc. that runs agents in cloud sandboxes. super.engineering's CLI is called se, and its former name, sc, still works.
