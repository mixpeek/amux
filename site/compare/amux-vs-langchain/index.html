amux vs LangChain

Runtime fleet management vs Python agent framework: they answer different questions. Here's when to use each, and when to use both. Updated September 2026.

Quick answer: amux manages live agent processes on your machine: self-healing, board coordination, phone monitoring, overnight operation. LangChain is a Python SDK for composing agent logic: tool calls, chains, retrievers. They sit at different layers and many teams use both.

What each tool actually is

amux is an open-source control plane for AI agent teams. It runs Claude Code, Codex CLI, or Gemini CLI sessions in isolated tmux windows, aggregates all sessions into one web dashboard, and keeps agents alive with a self-healing watchdog that auto-compacts context overflows and replays crashed sessions. It also ships built-in coordination primitives: a kanban board with atomic task claiming, a CRM, Gmail, a browser controller, and a scheduler. Single Rust binary, zero external dependencies.

LangChain is a Python (and JavaScript) SDK for building agent logic: composing sequences of LLM calls, tool invocations, retrievers, and memory into chains or graphs. LangGraph, LangChain's graph-based extension, lets you define agent state machines with conditional routing. LangSmith provides tracing and evaluation. The framework handles what the agent does; it doesn't manage the process running it.

Where LangChain fits: building agent logic

LangChain shines when you need to define what an agent does, step by step. Common patterns:

  • RAG pipelines: retrieve documents, pass them to an LLM, parse structured output. LangChain's retriever + chain + output parser pattern is mature and well-documented.
  • Custom tool sequences: if your agent needs to call specific APIs in a defined order, LangChain's tool definition + agent executor pattern is explicit and testable.
  • LangGraph state machines: complex multi-step workflows with conditional routing: "if the code review found bugs, run fix; otherwise run deploy."
  • Evaluation harnesses: LangSmith provides traces and evaluations for every LLM call, useful for debugging and improving custom agent behavior.

The trade-off: you write the agent logic. Every tool, every prompt template, every retry. For general coding tasks, Claude Code already handles all of that. You just describe what you want in natural language.

Where amux fits: running agents reliably

amux is the right layer when your goal is to run agents, not build them. It answers operational questions:

  • How do I run 20 agents at once? amux manages parallel tmux sessions, each with its own context, task, and output stream.
  • What happens when an agent crashes at 3am? amux's watchdog auto-restarts and replays the last message. The agent picks up where it left off.
  • How do 20 agents avoid working on the same task? The kanban board uses atomic claiming: once an agent claims a card, it's locked.
  • How do I check on agents from my phone? The iOS app and PWA give you the full dashboard: peek output, send instructions, move tasks.
  • How do agents hand off work to each other? Inter-session messaging, group routing, and the board's dependency tracking handle cross-agent coordination without custom code.

Using amux and LangChain together

The two tools are complementary. A common architecture:

  1. LangChain-built custom agents handle specialized logic (document processing, RAG, API workflows)
  2. Claude Code sessions handle general software development tasks
  3. All sessions (LangChain and Claude Code) run as amux sessions in the same fleet
  4. All are visible in the amux dashboard, coordinate via the same kanban board, and benefit from the same self-healing watchdog

The amux control plane doesn't care what's running in a tmux session. If your LangChain script runs from the terminal, it can run as an amux session.

amux vs LangGraph specifically

LangGraph (the graph-based multi-agent framework from LangChain) and amux both enable multi-agent workflows, but at different levels:

Question amux answers LangGraph answers
How does the agent decide what to do next? The model decides (no graph) Defined as a state graph with edges and conditions
How do multiple agents get tasks? Kanban board with atomic claiming; auto-drain for idle sessions Edges and subgraph invocations in your graph definition
What happens when a session crashes? Self-healing watchdog restarts and replays You handle it in your graph error nodes
How do I monitor from my phone? iOS app / PWA: live fleet view, peek output LangSmith web (no native mobile app)

Which one should you start with?

If your goal is to write software faster using AI (run parallel Claude Code agents, automate code review, ship features overnight), start with amux. Setup is 5 minutes, no agent logic to write, and Claude Code handles general software tasks out of the box.

If your goal is to build a custom AI workflow (a document processor, a RAG system, a specialized tool-calling agent), start with LangChain. You define the logic, and the framework provides the plumbing.

Many teams end up using both: LangChain for the custom parts, amux as the runtime layer that keeps everything running reliably.

Frequently asked questions

What is the difference between amux and LangChain?

amux is a runtime control plane: it manages, monitors, and heals Claude Code processes running on your machine. LangChain is a Python SDK for composing LLM calls, tools, and agent logic. amux doesn't define agent logic; LangChain doesn't manage live processes. They sit at different layers of the stack.

Can I use amux and LangChain together?

Yes. LangChain defines what your agent does; amux handles where it runs and what happens to it. If your LangChain script runs from the terminal, it can be an amux session, with the same dashboard visibility, self-healing watchdog, and phone monitoring as any other session.

Is LangChain better than Claude Code for coding tasks?

They solve different problems. Claude Code is a finished coding agent: it reads files, edits code, runs tests, and iterates based on your instructions. LangChain is a toolkit for building your own agents; you define every tool call and prompt. For general software development, Claude Code with amux is much faster to set up and requires no agent framework code.

Does amux support Python agents, not just Claude Code?

Yes. amux manages tmux sessions (any terminal process). Python scripts, Node.js servers, custom agent CLIs all run as amux sessions. You get the same dashboard, peek output, steering queue, and self-healing as Claude Code sessions.

What does amux cost vs LangSmith?

amux is free and open source (MIT + Commons Clause). LangSmith, LangChain's observability and evaluation platform, has a free tier for individual developers and paid tiers for teams. The amux dashboard runs locally: no SaaS subscription, no data sent to external services.
