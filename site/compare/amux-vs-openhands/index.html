amux vs OpenHands (OpenDevin) 2026

Autonomous single-agent sandbox vs open-source fleet orchestration. Different tools for different workflows, and why many teams use both. Updated August 2026.

OpenHands (formerly OpenDevin, by All Hands AI, ~42k GitHub stars) is an autonomous AI developer. You give it a task via a web UI, it spins up a Docker container, writes code, runs tests, searches the web, and fixes errors by itself until the task is done or it gets stuck. One task at a time in the default interface. amux is an open-source orchestration layer that runs a fleet of AI coding agents in parallel on your own machine. Where OpenHands goes deep on a single task, amux goes wide across 5-50 tasks simultaneously. Both tools are genuinely open source, both are free to self-host, and they complement each other rather than compete.

How each tool works

How OpenHands works

OpenHands is a fully autonomous AI software developer. You provide a task in natural language via the web UI or API, and it plans, executes, and iterates in a sandboxed Docker container until the task is complete. Inside the container it has access to a filesystem, a terminal, a browser, and your configured LLM. It can write code, run tests, install packages, search the web, and diagnose its own errors.

The agent operates in a continuous loop: observe state, think, act, observe result. It handles multi-step tasks that require planning, like "implement feature X with tests and a docs update" — without you guiding each step. The Docker sandbox means the agent's actions cannot affect your host machine beyond the project directory you mount.

OpenHands supports multiple LLM backends: Claude (via the Anthropic API), GPT-4, Gemini, and local models via Ollama. The cloud version at openhands.ai adds managed sandboxing and per-task billing. The OSS version is self-hosted and requires Docker and your own LLM API keys.

How amux works

amux is a control plane for a fleet of AI coding agents. Instead of one agent doing one task autonomously, amux manages 5-50 agents simultaneously, each running in its own tmux session on your local machine. Each agent gets tasks from a shared SQLite kanban board with atomic compare-and-swap claiming, so no two agents work the same task.

The self-healing watchdog monitors every session. When an agent nears its context limit, it auto-compacts; when it crashes, the watchdog restarts it and replays the last message so work continues without human intervention. The web dashboard and native iOS app let you peek into any session, send messages, and monitor token spend from anywhere.

amux is purpose-built around Claude Code but also manages Codex CLI and Gemini CLI sessions. It installs in ~30 seconds as a single Rust binary with no Docker, no containers, and no external dependencies beyond tmux.

When to use OpenHands

  • You have a single complex task that requires deep autonomy: write tests, fix failures, search for context, iterate.
  • You want an isolated Docker sandbox so the agent cannot affect your host filesystem.
  • You need multi-provider model support without committing to Claude Code.
  • You are exploring autonomous AI development and want a polished single-agent experience out of the box.

When to use amux

  • You want to run 5-50 coding tasks in parallel overnight and wake up to finished pull requests.
  • You are already using Claude Code and want to scale from 1 agent to a coordinated fleet.
  • You need shared task coordination across agents (no duplicate work, atomic claiming).
  • You want mobile monitoring via an iOS app or PWA while agents run unattended.
  • You want zero-overhead setup: no Docker, no containers, no cloud account.

Using amux and OpenHands together

These tools are not mutually exclusive. A practical workflow: use amux to coordinate the fleet and OpenHands for the tasks that benefit from deep sandbox autonomy.

Pattern 1: amux routes, OpenHands executes complex tasks. The amux board queues 50 tasks. Most go to Claude Code workers. Tasks flagged as "requires sandbox autonomy" route to an OpenHands CLI session managed by amux. amux monitors the OpenHands session alongside the rest of the fleet.

Pattern 2: OpenHands for research, amux for implementation. Use OpenHands to explore an unfamiliar codebase autonomously (browse files, run tests, understand the system). Distill the findings into specs. Push specs to the amux board. Run the implementation phase with 10 parallel Claude Code agents.

Pattern 3: amux manages OpenHands instances directly. amux manages any CLI process in a tmux session. You can run the OpenHands CLI inside a tmux session, assign it tasks from the amux board, and monitor it from the amux dashboard alongside other workers. You get the deep autonomy of OpenHands with the fleet visibility of amux.

What's new in amux — August 2026

Recent additions that change the comparison since this page was first written:

  • Connectors tab (OAuth broker): agents can now authenticate with third-party services once from the dashboard — Google, GitHub, Slack, or any custom OAuth provider. Every agent in the fleet shares the grant. No more pasting credentials into CLAUDE.md files. OpenHands handles credentials per-task; amux's broker is fleet-scoped.
  • Gmail batch API — inbox 4x faster: reading 480 emails now completes in ~5 API round-trips instead of 90. For agents that process email as part of business automation, this is the difference between a 2-second and a 12-second inbox sweep.
  • @-worker dropdown in scheduler: the scheduler command editor now autocompletes worker names with @-mention. Queue recurring jobs for specific agents without leaving the dashboard.
  • Server self-adoption (zero-downtime updates): the amux server detects a new binary on commit, exits, and launchd relaunches it — no manual restart, no dropped sessions.
  • Disk watchdog: weekly warning before caches fill the drive. On a fleet running 30+ agents, build caches accumulate fast; the watchdog alerts before ENOSPC.

Frequently asked questions

Is OpenHands the same as OpenDevin?

Yes. OpenDevin was renamed OpenHands in mid-2024 when the project moved to the All Hands AI organization. The GitHub repository is now at github.com/All-Hands-AI/OpenHands. The codebase, community, and goals are identical. Search results for "OpenDevin" will often surface OpenHands pages.

Does amux replace OpenHands?

No. They solve different problems at different levels. OpenHands is a fully autonomous agent for individual complex tasks: give it a task, it handles the planning and execution loop inside a Docker sandbox. amux is a fleet orchestration layer: it coordinates 5-50 coding agents running in parallel, with shared task queues, self-healing, and mobile monitoring. The two complement each other.

Can I run OpenHands as a worker inside amux?

Yes. amux manages any process inside a tmux session. You can run the OpenHands CLI inside a tmux session that amux monitors, assign it tasks from the amux kanban board, and watch its output from the amux dashboard alongside Claude Code or Codex workers. This gives you OpenHands' deep autonomy with amux's fleet visibility.

Which is better for overnight runs?

amux is purpose-built for overnight multi-task fleet operation. The self-healing watchdog auto-compacts agent context before it hits the limit, restarts crashed sessions, and replays the last message so no work is lost. You queue 50 tasks, close your laptop, and wake up to results. OpenHands is better suited for single complex tasks where you want deep autonomy: plan, write, run tests, fix failures, iterate.

What does OpenHands cost compared to amux?

amux is free open-source software. You pay only for the LLM API tokens your agents consume. There is no per-task fee and no per-seat charge. OpenHands cloud (openhands.ai) uses a per-task credit model on top of LLM API costs. The self-hosted OSS version is free but requires Docker and your own LLM API keys. For high-volume parallel workloads, amux's pay-only-for-tokens model scales more predictably.
