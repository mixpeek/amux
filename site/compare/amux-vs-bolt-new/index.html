amux vs Bolt.new

Greenfield browser generation vs. parallel agent fleet on your existing codebase. October 2026.

Quick answer: Bolt.new generates brand-new web apps in a browser sandbox with zero local setup. amux runs a fleet of parallel Claude Code, Codex, and Gemini CLI agents on your existing local codebase overnight, with usage-limit and reboot recovery, a kanban board, and mobile management. They target fundamentally different moments: Bolt.new for greenfield prototypes, amux for iterating on production code at fleet scale. Most developers use both.

Bolt.new (from StackBlitz) is a browser-based AI coding environment. You describe what you want; it generates a full-stack app in a WebContainer sandbox, with a live preview, Figma integration, and instant deployment. No local environment needed. Code stays in the cloud.

amux is an open-source control plane for running an AI engineering team from a single dashboard. It launches and monitors dozens of Claude Code, Codex, or Gemini CLI sessions simultaneously against your local codebase, coordinated via a shared kanban board, with a web dashboard and a native iOS app. Single Rust binary, MIT + Commons Clause, zero external runtime dependencies beyond tmux.

What's new in amux (October 2026)

Since the August 2026 version of this comparison, amux shipped several major features relevant to teams that use both Bolt.new and amux in their workflow:

  • Workspace isolation (AMUX_WORKSPACE_ISOLATION=1) — each agent gets its own git worktree and TMPDIR, so 20 parallel agents can work the same repo without file conflicts.
  • Vault secrets — encrypted API keys injected at agent launch, scoped global/group/worker, never in CLAUDE.md or git history.
  • Standing approvals — pre-approve recurring agent actions so overnight runs don't stall on permission prompts.
  • Companion chat — ask any running agent what it's doing in natural language from the iOS app or dashboard, without interrupting its work.
  • Goal keeper — set a goal string; amux checks every N turns and redirects the agent if it drifts.
  • Skill examples — amux infers example invocations from skill Markdown and surfaces them in the / dropdown.

The core difference: greenfield generation vs. fleet iteration

Bolt.new is a creation tool. Its power is speed-to-first-prototype: describe an app, get a working skeleton in seconds, iterate by chatting, preview in the browser. The WebContainer sandbox means nothing touches your local machine and there is no setup friction. That is the right model when you are validating an idea or onboarding a non-developer.

amux is an iteration tool. Its power is throughput on an existing codebase: queue 20 tickets on the board, have 10 agents claim tasks atomically, work overnight in parallel, and wake up to 20 pull requests. Delivery pauses at usage limits and resumes at the provider's reset, and stall alerts tell you when a session needs you, so you do not have to babysit the fleet. That is the right model when you have shipped code and need to ship more of it, faster.

When to use Bolt.new

  • You are validating a brand-new idea and want a working prototype in minutes, not hours
  • You have no existing codebase and no local development environment set up
  • You want a visual preview as you iterate — Bolt.new's live browser preview is first-class
  • You are working with a non-developer who needs to see results without touching a terminal
  • You are building a web app — Bolt.new's WebContainer is optimized for front-end and full-stack web projects

When to use amux

  • You have an existing codebase and need to parallelize work across it overnight
  • You want to run 10+ agents simultaneously on different branches or tasks without manual coordination
  • You need unattended overnight runs — amux holds work through usage limits and alerts you to stalls while you sleep
  • You want fleet visibility from your phone — check agent status, send messages, and review results from the iOS app
  • You are building beyond web apps — native apps, CLI tools, backend services, data pipelines, anything a terminal can run
  • Data privacy is non-negotiable — your code never leaves your machine

Why not both?

Many developers use Bolt.new and amux at different stages of the same project. Bolt.new is ideal for the first 10% — getting a working skeleton fast, before you have strong opinions about the architecture. Once the prototype is solid enough to export and commit, amux takes over for the remaining 90%: running parallel agents across the growing codebase, managing tickets on the shared board, and doing overnight sprints.

The handoff point is when your project graduates from "idea validation" to "I care about this code long-term." Bolt.new excels at the former; amux excels at the latter.

Frequently asked questions

What is the main difference between amux and Bolt.new?

Bolt.new generates brand-new web applications from prompts inside a browser sandbox. amux runs a fleet of parallel AI coding agents on your existing local codebase with overnight usage-limit resume, a shared kanban board, and mobile management. Bolt.new is for greenfield prototypes; amux is for iterating on real production codebases at fleet scale.

Can amux replace Bolt.new for prototyping?

Not directly. Bolt.new's strength is zero-setup, instant full-stack generation from a blank canvas in the browser. amux requires a local environment and an existing codebase. For rapid prototyping without any local setup, Bolt.new is the right tool. Once a prototype is solid enough to export and commit, switching to amux enables parallel agent iteration at far higher throughput.

Does Bolt.new support parallel AI agents?

No. Bolt.new is a single-session, single-agent tool. amux is purpose-built for parallelism: atomic task claiming via SQLite compare-and-swap prevents two agents from duplicating work, git worktree isolation prevents merge conflicts, and stall detection flags any session that stops overnight.

Is there an open-source version of Bolt.new?

Yes. Bolt.diy (formerly oai-like) is an open-source fork of the Bolt interface that you can self-host and configure with multiple AI providers. However, it is still a single-session browser tool and does not add fleet orchestration, overnight runs, or a shared kanban board. amux and Bolt.diy solve different problems.

Is amux a Bolt.new alternative?

For existing codebases: yes. amux runs parallel Claude Code, Codex, and Gemini CLI agents against your local repository, with usage-limit and reboot recovery, a shared kanban board, and mobile monitoring. For greenfield prototyping in the browser with zero local setup, Bolt.new has no direct equivalent in amux. Most developers use both at different stages of their projects.
