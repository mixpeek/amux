amux vs sandboxed.sh (Open Agent)

Both self-hosted. Different isolation models. Updated October 2026.

Quick answer: sandboxed.sh runs agents in isolated Linux workspaces, which gives strong execution isolation at the cost of more infrastructure. amux runs agents as tmux sessions directly on your machine: one Rust binary, no containers, self-healing watchdog, phone dashboard, and a full built-in kanban board. If you want to run your own trusted coding agents on an existing codebase with minimal setup, amux is the lower-friction choice.

What each tool is

sandboxed.sh (Open Agent) provisions isolated Linux workspace environments for running AI agents. Each agent run gets its own clean workspace, which provides strong isolation for untrusted or security-sensitive workloads. It has a web dashboard and mobile app for monitoring.

amux is an open-source control plane for running an AI engineering team directly on your own machine. It launches Claude Code, OpenAI Codex CLI, or Gemini CLI as tmux sessions, monitors them with a self-healing watchdog, and exposes a web dashboard at localhost:8824 and an iOS app. One Rust binary. No containers. No external dependencies.

Isolation model: containers vs worktrees

The sharpest difference is how each tool handles agent isolation.

sandboxed.sh gives each agent run a full Linux workspace container. This is the right call when you need hard security boundaries: running untrusted code, red-teaming, or workflows where one agent must never see another's files. The trade-off is infrastructure overhead and slower startup.

amux takes a lighter approach. By default, all workers share the host filesystem in tmux sessions. With AMUX_WORKSPACE_ISOLATION=1 per worker, amux creates a dedicated git worktree and isolated TMPDIR for that worker, so each agent has its own view of the codebase without touching others' in-progress changes. This is enough for most coding teams, costs no extra infrastructure, and starts in milliseconds.

The rule of thumb: if your agents run trusted code on your own codebase, amux worktree isolation is the right level. If you're running untrusted third-party code or need OS-level separation, sandboxed.sh's container model is stronger.

Running agents overnight

amux is purpose-built for long-running unattended workloads. Three features work together:

  • Self-healing watchdog. If an agent crashes, hangs, or exits unexpectedly, the watchdog restarts it within seconds. You configure the restart policy per worker.
  • Account rotation. When a Claude Code session hits its API usage limit, amux automatically rotates to the next verified account in your pool. No manual intervention, no sessions sitting idle at a rate-limit prompt.
  • Phone dashboard. The iOS app and mobile PWA show live session status, let you send prompts, and surface any alerts. You can check on an overnight run without opening a laptop.

Which should you choose?

Choose sandboxed.sh if:

  • You need strong OS-level isolation between agent runs
  • You're running untrusted code or security-sensitive tasks
  • Container infrastructure is already part of your stack

Choose amux if:

  • You want to run a team of trusted coding agents on your own codebase
  • You want the lowest-overhead setup (one binary, no containers)
  • You need a full built-in control plane: kanban board, scheduler, secrets vault, browser automation, phone app
  • You're running agents overnight and need self-healing + account rotation

Frequently Asked Questions

What is the main difference between amux and sandboxed.sh?

amux runs AI agents (Claude Code, Codex, Gemini CLI) as tmux sessions directly on your own machine, with a self-healing watchdog, phone dashboard, and built-in kanban board. sandboxed.sh (Open Agent) runs agents inside isolated Linux workspaces. amux is zero-infrastructure: one install command, one Rust binary, your existing API keys.

Which is better for running agents overnight unattended?

amux is designed for overnight unattended runs. The watchdog automatically restarts hanging or crashed agents, amux rotates across a pool of verified Claude Code accounts when one hits its usage limit, and the iOS app shows live status so you can check progress from anywhere.

Does amux have workspace isolation like sandboxed.sh?

Yes. amux has opt-in workspace isolation (AMUX_WORKSPACE_ISOLATION=1) that gives each worker its own git worktree and temporary directory. This is lighter-weight than sandboxed.sh's full Linux workspace containers, but covers most coding-team use cases without any container infrastructure.

Can I use amux and sandboxed.sh for the same project?

In principle yes. sandboxed.sh is well-suited for tasks requiring strict execution isolation (untrusted code, security workloads). amux is strong for running a team of trusted coding agents on an existing codebase with low overhead. The two can complement each other if your workflow has both kinds of tasks.

Is amux free?

The core amux server is MIT licensed and free forever. The only paid option is amux Cloud ($20/mo), which adds a stable public tunnel URL at https://<id>.t.amux.io/. Everything else including the dashboard, watchdog, board, scheduler, and secrets vault is free and self-hosted.
