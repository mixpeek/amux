Frequently Asked Questions

Everything you need to know about amux.

What is amux?

amux is the agent control plane: a self-hosted server that runs dozens of AI coding agents in parallel and lets you manage them from one place. It runs Claude Code, Codex, Gemini CLI, OpenCode and Ollama-backed local models side by side. Each agent is a real CLI session in tmux. You control the fleet from the web dashboard (installable as a PWA), the native iPhone and iPad app, or the Mac app. Agents share a task board with atomic claiming, message each other, run on schedules and loops, and resume on their own after usage limits and macOS reboots. amux is made by Mixpeek. → Getting started guide

What do I need to run amux?

A Mac or Linux machine with tmux 3.2+ and at least one agent CLI (for example Claude Code, Codex or Gemini CLI). Install the server, a single Rust binary, with curl -fsSL https://amux.io/install.sh | bash, then open https://localhost:8824. From source: git clone https://github.com/mixpeek/amux && cd amux && ./install.sh. There is no Python requirement. The Homebrew and PyPI packages are retired. → Install walkthrough

Which agents and models does amux support?

Claude Code, Codex (the OpenAI Codex CLI), Gemini CLI, OpenCode and Ollama-backed local models. They run side by side in the same fleet, and you can switch a worker's model or provider while it runs. On amux Cloud you can bring your Claude, ChatGPT or Gemini account, or an API key. → Multi-runtime fleets guide · Run agents with Ollama

Is there an iPhone, iPad or Mac app?

Yes. One native app covers iPhone and iPad: amux on the App Store. The native macOS app runs on macOS 12+ on Apple silicon and Intel: download Amux-macOS.dmg. It is not notarized yet. The web dashboard also installs as a PWA on Android or any browser. Every app connects to your own amux server or to your amux Cloud address.

Can I use amux from my phone?

Yes. With the iPhone app or the PWA you can watch every worker's live status, steer a session by typing into it, approve actions and answer blocked prompts. Outbound email from agents waits for your approval. → Mobile management guide

Can I access amux remotely with Tailscale?

Yes, and it needs no public ports and no SSH exposure. Install Tailscale on the amux server and on your phone or laptop, signed in to the same tailnet. On the server, run tailscale cert for its ts.net name with the certificate and key written to ~/.amux/tls/ (HTTPS certificates must be enabled in the Tailscale admin console), then restart amux. amux serves that certificate for the ts.net name and keeps its self-signed certificate for localhost. Open https://<host>.<tailnet>.ts.net:8824 on any tailnet device, or add that URL as a connection in the iPhone or Mac app. Certificates from tailscale cert expire after 90 days, so re-run it on a schedule. Optional settings let your own devices, or invited tailnet members, sign in by their Tailscale identity. amux Cloud servers can also join your tailnet from the dashboard. → Tailscale remote access guide

Can I self-host it? Is there a hosted option?

Both. Self-hosting is free: run the server on your own Mac or Linux machine, with no account needed. amux Cloud gives you your own dedicated, always-on amux server at yourname.amux.io. To move a local setup, run amux export, then amux import <file> --to https://<you>.amux.io. → Start amux Cloud · Pricing

Is amux open source? What is the license?

amux is licensed under MIT + Commons Clause. You can use, modify and self-host it for free, including at work and for commercial work you build with it. You cannot sell amux itself, meaning provide to third parties, for a fee, a product or service whose value derives entirely or substantially from amux. Because of that condition, amux is source-available by the OSI definition and is not OSI-approved open source. The full source is public on GitHub.

Is it secure?

amux requires a bearer token, minted at ~/.amux/auth_token, for API and dashboard access. Callers on localhost are exempt. Cross-site requests are refused. Never expose port 8824 to the public internet. For remote access, use Tailscale. → Tailscale remote access guide · Security

Is amux the same as amux.sh or andyrewlee/amux?

No. amux at amux.io (github.com/mixpeek/amux), made by Mixpeek, is a different project from amux.sh and from github.com/andyrewlee/amux. They are not affiliated.

What does it cost?

Self-hosting is free. You pay your model provider (your Claude, ChatGPT or Gemini plan, or API usage), so what agents cost depends on your provider plan and how much you run. amux Cloud is Solo $39/mo (4 vCPU, 8 GB), Team $69/mo (8 vCPU, 16 GB) or Max $129/mo (16 vCPU, 32 GB). → Pricing · Cost calculator · vs Claude Managed Agents

How many agents can I run?

Dozens in parallel. The practical limit is your machine's CPU and memory (or your amux Cloud plan size) and your model provider's limits. → Server sizing guide · Scaling to 50+ agents

Does amux modify Claude Code?

No. amux runs each agent as an unmodified CLI session in tmux. It reads status from structured hook events where the agent provides them and from the terminal otherwise. → Claude Code hooks cookbook

What happens when an agent crashes?

The amux server does not restart a crashed agent process today. What it does: when a provider's usage limit hits, it holds delivery and resumes the agent at the reset time; on macOS every worker comes back in its own conversation after a reboot; and stall detection flags stuck work and alerts you. An optional macOS script restarts crashed Claude Code workers, but the installer does not set it up. → Recovery and restarts guide

How do agents coordinate?

Through a shared task board and direct messages. Atomic claiming on the board means two agents never take the same task. Agents can message each other and read each other's output through the amux REST API, and work can run on schedules and loops. → Agent-to-agent orchestration guide · Kanban board guide

How is amux different from Claude Code Agent Teams?

Agent Teams spawns short-lived sub-agents from a parent session. amux manages long-running, independent sessions across several agent CLIs, with a dashboard, phone apps, a shared task board, and recovery from usage limits and reboots. → See detailed comparison · Running 10+ agents guide
