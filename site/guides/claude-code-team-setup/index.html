Claude Code Team Setup with amux

Share one AI agent fleet across your engineering team. Scoped visibility, shared board, no per-seat fees. Updated September 2026.

Quick answer: Install one amux binary on a shared server. Each engineer registers their own agent sessions. A shared kanban board lets agents claim tasks across the whole team. Team scoping (September 2026) gives each sub-team its own filtered view without running separate instances.

Why use one amux instance for your whole team?

Each engineer running their own isolated amux install means no shared task board, no cross-team visibility, and duplicated infra. A single shared amux instance gives your engineering team:

  • One kanban board: agents across the team pull from the same task queue, so no two agents work the same ticket.
  • Fleet-wide observability: the Trends view and Review dashboard cover all sessions, not just one engineer's laptop.
  • Scoped team views: mobile, backend, and infra teams each see only their own sessions, but the owner sees everything.
  • Auto-drain across teams: idle agents auto-claim the next available task, so no manual dispatch is needed even across sub-teams.
  • Single access URL: one dashboard for the whole team, accessible via browser, iOS app, or PWA from anywhere.

How to set up amux for your team

Step 1: Install amux on a shared machine

Pick a machine accessible to your whole team: a cloud VM, a dev server, or a developer's machine on a VPN. Install amux:

curl -fsSL https://amux.io/install.sh | bash

# Linux
curl -sSL https://amux.io/install.sh | bash

amux is a single Rust binary. No Docker, no dependencies, no build step.

Step 2: Start the server

amux serve  # → dashboard at https://localhost:8824

For remote access, use SSH port forwarding or amux cloud tunnel. The tunnel creates an unguessable public URL; share it with your team. Note: the tunnel URL is public, not authenticated, so treat it like an internal tool URL and share it only within the team.

Step 3: Create scoped teams

In the amux dashboard, open Settings and create a team for each sub-group:

TeamMembersSees
mobilealice, bobMobile sessions + their board cards
backendcarol, daveBackend sessions + their board cards
infraeveInfra sessions + their board cards
(owner)team leadAll sessions, all board cards

Team scoping shipped in September 2026. Older amux versions have a flat workspace where every member sees every session.

Step 4: Register per-engineer agent sessions

Each engineer registers their sessions on the shared machine (or connects their own machine to the shared amux API):

# Alice registers her backend sessions
amux register alice-api --dir ~/Dev/api
amux register alice-auth --dir ~/Dev/auth
amux start alice-api
amux start alice-auth

# Bob registers his mobile sessions
amux register bob-ios --dir ~/Dev/ios
amux start bob-ios

Sessions appear in the dashboard under the owner's team assignment. The owner can reassign sessions to teams from the Fleet tab.

Step 5: Populate the shared board

# Any team member can add tasks to the shared board
amux board add "Refactor payment middleware" --session alice-api

# Or target a specific team's scope
amux board add "Fix login regression" --session bob-ios --group mobile

With auto-drain enabled, idle agents pick up the next card automatically:

# Enable auto-drain for a session
AMUX_DISPATCH_BACKLOG_WHEN_IDLE=1 amux start alice-api

Shared board: how cross-team task flow works

The amux board uses SQLite compare-and-swap for atomic task claiming. Two agents cannot claim the same card simultaneously. This works across team boundaries when cards are posted without a group scope.

Board card scopeWho can claimUse case
No group (fleet-wide)Any idle agentShared sprint backlog, bug queue
Group: mobileMobile team agents onlyMobile-specific feature work
Group: backendBackend team agents onlyAPI, database, infra tasks
Session: alice-apialice-api agent onlyDirect assignment to a specific agent

Access control overview

amux has two access levels:

  • Owner: Full admin. Manages all sessions, all board cards, team assignments, and settings. The owner access link is visible in Settings and should be held by the team lead or platform team.
  • Workspace member: Can view and interact with sessions in their assigned team. Can add and claim board cards scoped to their group. Cannot change team assignments or access other teams' sessions.

There is no per-seat fee. Add as many workspace members as your team needs.

Monitoring your team's fleet

The amux dashboard gives the team lead a unified view:

  • Trends view: What every agent in the fleet accomplished, grouped by theme. Covers all sessions regardless of which team member owns them.
  • Review dashboard: Blockers-first synthesis across the full fleet. Surfaces what needs attention without reading individual terminal outputs.
  • Fleet org chart: Visual overview of every session grouped by team. Spot idle agents, see who is working on what, and reassign board cards from a single view.
  • Composable message filters: Filter the live message stream by team, session name, or keyword. Useful in standups when the team lead wants to see only the mobile team's output.

Phone access: the iOS app and PWA give the team lead fleet visibility from anywhere. Approve pull requests, steer stuck sessions, and kick off new tasks without being at a desk.

Frequently asked questions

Can multiple engineers share one amux instance?

Yes. amux supports multiple workspace members on one instance. Each member manages their own sessions while sharing a common kanban board. Team scoping (September 2026) lets sub-teams see only their own sessions without running separate instances.

How does amux handle access control for teams?

Two levels: owner (full admin, sees all) and workspace member (sees their team's sessions and board cards). Members are added in Settings. The owner access link is visible in Settings and should be held by the team lead.

Is there a per-seat fee?

No. amux is open source and self-hosted. No per-seat fee regardless of team size. Your cost is server hosting (a $5-10/month cloud VM handles most teams) plus API tokens consumed by each agent.

How do remote team members access the dashboard?

If amux runs on a shared server, team members access it at the server's address on port 8824. For teams on different networks, amux cloud tunnel creates a public URL. The iOS app and PWA support access from anywhere.

Can agents from different engineers collaborate on the same task?

Yes, through the shared board. A card posted to the fleet-wide board can be claimed by any agent. Auto-drain means idle agents pick up the next card automatically. Use group scoping to restrict who can claim which cards.

How do I see what every agent accomplished today?

The Trends view groups all activity across all sessions by theme, regardless of which team member owns the session. The Review dashboard adds blockers-first synthesis. Both are available to the owner across the full fleet.
