Claude Code vs Codex vs Gemini CLI: Running a Multi-Runtime AI Agent Fleet

September 2026 — orchestrating Claude Code, OpenAI Codex, and Gemini CLI agents from one dashboard

amux runs Claude Code, Codex, and Gemini CLI agents from one dashboard — open source, 394+ stars. View amux on GitHub ★

You don't have to pick one AI coding runtime. Claude Code, OpenAI Codex CLI, and Gemini CLI each have different strengths — and a mature agent workflow uses all three in parallel, each assigned to the tasks it handles best. amux is the control plane that makes this work: one dashboard, one kanban board, one phone view, regardless of which runtime each agent uses.

Quick answer: Use Claude Code for complex reasoning and refactoring, Codex for Python scripts and data pipelines, Gemini CLI for long-context tasks and free-tier work. Run all three in amux — they share the same kanban board, you monitor all from your phone, and the self-healing watchdog covers all sessions equally.

When to run multiple runtimes in the same fleet

Mixed fleets make sense when different tasks have different runtime requirements:

  • Cost tiering: put Claude Opus on the highest-complexity implementation tasks; use Codex on the high-volume mechanical work (migrations, test generation, linting fixes). You get Opus-quality output where it matters and Codex-speed output where it doesn't.
  • Context size: Gemini's 1M-token context handles the "understand this whole codebase" prompt that would overflow a Claude session. Use Gemini for the analysis pass, Claude Code for the implementation.
  • Free tier cadence: Gemini's 1,500 requests/day free tier covers low-priority tasks like documentation refreshes and README updates at zero API cost. Save your Anthropic credits for work that needs Claude's reasoning.
  • Specialization by language: Codex trained heavily on Python-heavy GitHub data and performs especially well on data science, scripting, and ML tasks. Claude Code excels at system-level work (Rust, Go, multi-service architectures).

How amux orchestrates Claude Code, Codex, and Gemini CLI together

amux treats every runtime as a session. It doesn't care which binary is running inside the tmux window — it reads terminal output, delivers steering messages, and tracks board state for all of them identically.

Register sessions by runtime

# Claude Code session
amux register auth-agent --dir ~/Dev/myproject --yolo
amux start auth-agent              # launches Claude Code

# Codex session (same project, different task)
amux register data-pipeline --dir ~/Dev/myproject --yolo --runtime codex
amux start data-pipeline           # launches Codex CLI

# Gemini CLI session (long-context analysis)
amux register codebase-qa --dir ~/Dev/myproject --yolo --runtime gemini
amux start codebase-qa             # launches Gemini CLI

All three sessions appear on the same dashboard. The board shows which session owns which task, regardless of runtime.

Shared kanban board across runtimes

The amux kanban board is runtime-agnostic. Tasks are plain text with a status field. Any session — Claude Code, Codex, or Gemini — can claim, work, and close a task. Your CLAUDE.md (or equivalent per-runtime config) tells each agent how to interact with the board API.

# For Codex and Gemini sessions, add to their system prompt:
# Board API: GET $AMUX_URL/api/board → claim tasks via POST /api/board/TASK_ID/claim
# When done: PATCH /api/board/TASK_ID {"status":"done","desc":"Result: ..."}

# Auto-drain (September 2026): sessions self-assign their next task when idle
amux board drain on auth-agent      # Claude Code agent auto-drains
amux board drain on data-pipeline   # Codex agent auto-drains

Phone monitoring across all runtimes

The amux iOS app and PWA show all sessions in one list, regardless of runtime. Peek output, send a steering message, restart a crashed session — all from your phone, all runtimes unified.

Practical patterns for mixed fleets

Analysis-implementation split

Use a Gemini CLI session to analyze your codebase (full 1M-token context), produce a structured task list, and push it to the amux board. Claude Code sessions then pick up implementation tasks from the board atomically. You get the best of both: Gemini's scale for understanding, Claude's precision for building.

# Gemini session: analyze and queue tasks
amux send codebase-qa "Read the full codebase in packages/api/, identify the 10 highest-priority tech-debt items, and add each as a board task: amux board add 'Fix: [item]'"

# Claude Code sessions: pick up and implement those tasks automatically
amux board drain on auth-agent
amux board drain on payments-agent

Cost-optimized test generation

Test generation is high-volume but mechanical. Assign Codex sessions to generate tests in parallel — Codex is fast and handles the pattern-matching work well. Reserve Claude Code sessions for the business logic that needs deeper reasoning.

Language-specialized routing

Route tasks by file extension in your CLAUDE.md: Claude Code for *.rs, *.go, *.ts architecture work; Codex for *.py, *.ipynb, *.sql; Gemini for *.md, *.txt, documentation refreshes.

Switching runtimes mid-sprint

You don't have to commit to a fleet composition at the start of a sprint. amux lets you add and remove sessions at any time. If a Claude Code session is blocked on an API rate limit, spin up a Codex session and route the next task there. The board state stays consistent — whoever claims the task owns it until done.

Self-healing across runtimes

amux's watchdog works the same for all runtimes: if a Codex or Gemini session crashes, it restarts and replays the last message exactly as it does for Claude Code. The only difference is context compaction — /compact is a Claude Code-specific command. For Codex and Gemini sessions that overflow context, the watchdog restarts with a fresh context (losing conversation history but keeping the board state and task description).

Getting started with a multi-runtime fleet

  1. Install amux: curl -fsSL https://amux.io/install.sh | bash
  2. Install each runtime you plan to use: Claude Code, Codex CLI, Gemini CLI
  3. Register sessions by runtime: amux register <name> --runtime <claude|codex|gemini>
  4. Write a shared CLAUDE.md with the board API calls and task-claiming workflow — reference CLAUDE.md templates
  5. Enable auto-drain so idle sessions self-assign: amux board drain on <session>
  6. Monitor from your phone — all runtimes in one dashboard view

Frequently asked questions

What is the difference between Claude Code, Codex, and Gemini CLI?

Claude Code is Anthropic's terminal-based agent, strongest at complex refactoring and system-level reasoning. OpenAI Codex CLI is MIT-licensed, fast, and excels at Python and data work. Gemini CLI targets long-context tasks (1M-token window) and has a generous free tier. All three run as terminal agents that can write, edit, and test code autonomously.

Can I run Claude Code and Codex agents in the same project?

Yes. With amux, each agent is an independent session. You can assign Claude Code sessions to architecture and refactoring tasks, Codex sessions to Python scripts and data pipelines, and Gemini CLI sessions to documentation and long-context analysis — all monitored from one dashboard.

Which AI coding runtime is best for running overnight unattended?

Claude Code has the most mature self-healing story when paired with amux. Context compaction (/compact), crash recovery, and last-message replay are well-tested for overnight runs. Codex and Gemini CLI work well for bounded tasks where the session is likely to complete within a few hours.

How does cost compare between the three runtimes?

Codex CLI is MIT-licensed (free); you pay for OpenAI API usage. Gemini CLI has a free tier (1,500 requests/day on Gemini 2.0 Flash). Claude Code bills through Anthropic API pricing — Sonnet is the recommended daily driver for cost-quality balance. In a mixed fleet, route high-volume mechanical work to Codex or Gemini and reserve Claude for tasks requiring deep reasoning.

Does amux support Gemini CLI agents?

Yes. amux registers any terminal process. Start Gemini CLI in a tmux window, register it, and it appears on the dashboard alongside Claude Code and Codex sessions with the same peek, steer, and self-healing capabilities.
