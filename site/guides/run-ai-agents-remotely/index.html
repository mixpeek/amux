Run AI Coding Agents on a Remote Server

Use amux-remote to manage a parallel fleet of Claude Code, Codex, and Gemini CLI agents on a dedicated server — from your laptop, phone, or any browser. Published August 2026.

Run your AI engineering team on a dedicated server overnight
amux: open-source fleet control plane for Claude Code, Codex & Gemini CLI — 373+ stars, MIT licensed, single Rust binary.
View amux on GitHub ★

amux lets you run 10-50 AI coding agents in parallel on any machine. With amux-remote, that machine doesn't have to be your laptop. Point amux at a remote server — a cloud VM, a home server, a dedicated machine — and manage the entire fleet from your local terminal, browser, or phone.

The remote server runs all the agents. Your local machine is just the control surface. Close your laptop, put your phone in your pocket — the agents keep working.

Why run agents on a remote server?

  • No laptop limits — a dedicated server has more RAM, more CPU cores, and doesn't compete with your browser or other apps. A 32 GB server can run 50+ agents simultaneously.
  • Always-on — the server stays running when you close your laptop, lose your network connection, or put your machine to sleep. Overnight runs complete reliably.
  • Manage from anywhere — check fleet status from your phone via the amux iOS app or PWA. Send a message to redirect an agent from the couch. Review completed PRs from the coffee shop.
  • Separate compute from control — run expensive agents (GPT-4o, Claude Opus) on a high-memory server without paying for a premium laptop. Your local machine just needs a browser.

How to set up amux-remote (5 minutes)

Step 1: Install amux on the remote server

SSH into your remote machine:

ssh user@your-server

# Install amux (single Rust binary)
brew install amux
# or download from GitHub releases for Linux
curl -sSL https://github.com/mixpeek/amux/releases/latest/download/amux-linux-x86_64 -o /usr/local/bin/amux
chmod +x /usr/local/bin/amux

# Start the amux server
amux serve  # listens on port 8824

The server generates an auth token on first run at ~/.amux/auth_token.

Step 2: Get the auth token

cat ~/.amux/auth_token
# Output: aAbBcCdDeE1234...  (copy this)

Step 3: Find the server's reachable IP

Option A — Tailscale (recommended):

tailscale ip -4
# Output: 100.64.0.1  (your Tailscale VPN address)

Tailscale creates a private mesh between your devices — no port forwarding or firewall changes needed. Install Tailscale on both the server and your local machine.

Option B — Direct IP (same network or port-forwarded):

hostname -I
# Output: 192.168.1.50

Step 4: Configure your local machine

cat > ~/.amux/remote.env << 'EOF'
AMUX_URL=https://100.64.0.1:8824
AMUX_TOKEN=aAbBcCdDeE1234...
EOF
chmod 600 ~/.amux/remote.env

# Load when you want to manage the remote fleet
source ~/.amux/remote.env

Step 5: Verify the connection

source ~/.amux/remote.env
curl -sk $AMUX_URL/api/health | python3 -m json.tool
# Should return {"status":"ok","version":"..."}

# List remote sessions
amux list

# Check the board
amux board

# Open the dashboard
open $AMUX_URL

Once connected, every amux command operates on the remote fleet. Start sessions, peek at output, send messages — all from your local terminal or the web dashboard at $AMUX_URL.

Each Claude Code, Codex, or Gemini CLI session uses 200-400 MB of RAM. CPU is rarely the bottleneck — agents spend most of their time waiting for API responses. Disk I/O matters for worktree-heavy workflows.

Overnight remote workflow

A typical remote overnight session:

  1. Evening — SSH into the remote server (or use the local amux CLI with AMUX_URL set). Add tasks to the board. Start 10-20 sessions. Confirm agents are running.
  2. Night — close your laptop. Agents run on the remote server. The self-healing watchdog handles context overflow, crashes, and stuck prompts automatically.
  3. Morning — open the amux iOS app or PWA. Check the board for completed tasks. Peek at session output for any that need review. Merge the PRs your agents opened.

Security considerations

  • Auth token — treat the amux auth token like a password. Store it in ~/.amux/remote.env with chmod 600. Never paste it into a shell command that logs to history.
  • Tailscale ACLs — restrict amux server access to your own Tailscale devices using Tailscale ACL rules. No device outside your tailnet can reach the server.
  • TLS — amux serves HTTPS with a self-signed certificate by default. Use curl -sk (not -k alone) for local trust, or add a proper TLS certificate for production setups.
  • Agent credentials — API keys (Anthropic, OpenAI, Google) live in the remote server's environment or ~/.amux/server.env. They never leave the server machine.

Frequently asked questions

What is amux-remote?

amux-remote is the capability to point your local amux CLI and browser dashboard at a remote amux server. Set AMUX_URL to the remote server's address and AMUX_TOKEN to its auth token. All amux commands — board, send, peek, list — operate on the remote fleet. The dashboard at $AMUX_URL is served from the remote server and works in any browser or phone.

Why run agents on a remote server instead of locally?

Three reasons: compute, stability, and mobility. A dedicated server can run 20-50 agents overnight without competing with your laptop's battery and RAM. It stays on when you close your laptop. And you can check progress from your phone from anywhere — the agents keep running regardless of where you are.

Does amux-remote require Tailscale?

No, but Tailscale is the recommended approach. It creates a private VPN mesh between your devices without port forwarding or firewall changes — any device on your Tailscale network can reach the server at its stable Tailscale IP. Direct IP works too if you're on the same network or willing to configure port forwarding.

Can I manage a remote fleet from my iPhone?

Yes. Open the amux PWA or iOS app and point it at $AMUX_URL (the remote server's Tailscale IP). You get the full dashboard — sessions, board, fleet health, peek — on your phone. The iOS app is on the App Store; the PWA works in Safari by opening the dashboard URL and adding to home screen.

What if the remote server restarts?

Configure amux as a system service (launchd on macOS, systemd on Linux) so it starts automatically on boot. The amux watchdog resumes monitoring sessions that were running before the restart. Any session that was in the middle of a task will replay its last message and continue.

How is this different from just SSH-ing into the server?

SSH gives you a raw terminal. amux-remote gives you the full fleet management API, dashboard, and CLI — all the high-level tools without opening a terminal. Check the board with amux board, peek at a session with amux peek myagent, send a message with amux send myagent "continue". The web dashboard at $AMUX_URL is a full phone-friendly UI served from the remote machine.
