AI Agent Companion Chat

Ask your AI coding agents what they are doing — in plain language, from your phone. The companion sees the agent's recent activity log so answers are grounded in actual work, not hallucination.

You queue 20 Claude Code agents before bed. It is 11pm, you are on the couch, and one of them sent you an owner alert. You want to know what it finished, what it is stuck on, and whether it needs anything from you — without SSHing into your server or reading a wall of terminal output on a 6-inch screen.

That is what companion chat is for.

Open any agent's card in the amux iOS app or web dashboard and tap the chat icon. You get a panel where you can type questions in plain English. The companion automatically loads the agent's most recent 15 recorded actions before answering — prompts received, files edited, board mutations, tool calls, steering messages — so when you ask "what are you working on?", it answers from what the agent actually did, not from its original task description.

The activity log: what the companion sees

Every action an amux session takes is recorded in its command history. This includes:

  • Prompts sent to the session (initial task, steering messages, owner messages)
  • Board mutations (tasks claimed, tasks marked done, evidence recorded)
  • Agent self-reports via amux board progress
  • Scheduled messages delivered to the session
  • Context compaction events (when the watchdog compressed the context)
  • Peer messages received from other agents

When you open companion chat for a session, the interface loads the 15 most recent entries from this history and includes them in the companion's context. The companion can then answer questions about what the agent is doing with specifics rather than generalities.

This matters most for long overnight runs, where the current task is often far removed from the original prompt. An agent that started with "write unit tests for the auth module" might be three hours in and currently working on a test fixture for a token refresh edge case. The activity log captures that drift; a raw task description does not.

How to use companion chat

From the iOS app

  1. Open the amux iOS app (download from the App Store). You will see your session list with status indicators.
  2. Tap a session card. The detail panel slides up with tabs: Overview, Terminal, Chat.
  3. Tap the Chat tab. The companion chat interface loads. Recent activity entries appear at the top of the conversation view.
  4. Type your question and send. The companion responds within a few seconds.

From the web dashboard

  1. Open your amux dashboard (default: https://localhost:8824, or your amux tunnel URL for remote access).
  2. Click the chat bubble icon on any session card, or click a session's name to open its detail panel and select the Chat tab.
  3. Type and send. The activity log is loaded automatically; no configuration needed.

Questions worth asking

These work well with the activity log in context:

  • "What are you working on right now?" — The companion synthesizes the last few actions into a short summary.
  • "What did you finish in the last hour?" — Board mutations and progress notes show completed tasks with timestamps.
  • "Are you stuck anywhere?" — If the agent hasn't made a board mutation or produced output in a while, the companion flags it.
  • "What files have you edited?" — Tool call records capture file edit operations.
  • "What should I review?" — Board entries marked done but not verified surface here.

Redirecting mid-task

Messages you send in companion chat are delivered to the agent as new prompts. The agent reads the message at its next turn boundary and responds.

Useful redirections:

  • "Stop what you are doing and give me a status summary" — useful before sleeping to get a clean state checkpoint.
  • "Skip the edge cases for now and move on to the next task" — if the agent is spiraling on one case.
  • "The API I described changed — use the new signature in docs/api.md" — late-breaking context that wasn't in the original prompt.
  • "Mark that task done and pull the next one from the board" — if the agent's self-reporting stalled.

Companion chat vs reading terminal output

Approach What you see Usable on phone? Grounded in actual work?
Terminal output (peek) Raw character stream, ANSI codes, JSON tool calls, progress bars Barely — dense, hard to parse on small screen Yes, but requires manual reading and interpretation
Board status Task titles, status labels, evidence snippets Yes Yes — but only covers board-tracked work, not in-progress actions
Owner alerts Push notification with a short message from the agent Yes Yes — but only fires when the agent sends one explicitly
Companion chat Plain-language Q&A with activity-log context automatically loaded Yes — purpose-built for phone Yes — synthesized from the last 15 recorded actions

The four approaches are complementary. Owner alerts tell you when something needs attention. Board status gives you the task-level picture. Terminal peek gives you the raw signal when you need to debug. Companion chat is the natural-language layer on top — the right surface when you want a fast answer and are not in front of a workstation.

Example conversation

This shows what a real companion chat exchange looks like for an overnight run (agent is working on test coverage):

companion chat — agent: coverage-worker
You (11:42pm)
What are you working on right now?

coverage-worker
I'm writing a test for the token refresh edge case in auth/session.ts —
specifically the scenario where the refresh token has expired and the API
returns a 401 on the re-auth attempt. I claimed this from the board (task
AUTH-14) about 20 minutes ago. Before that I finished AUTH-11 through
AUTH-13 (the happy path and the two common error states). AUTH-14 is taking
longer because the test needs a mock of the retry interceptor.

You (11:44pm)
Are you stuck anywhere?

coverage-worker
The interceptor mock is the only blocker. The existing test fixture doesn't
expose the retry count, so I'm writing a thin wrapper. Should have it in the
next few turns. If the approach doesn't work I'll move on and flag AUTH-14
as needs-review.

You (11:45pm)
Good, carry on. Wake me if you get stuck for more than 30 minutes.

coverage-worker
Understood. I'll send an owner alert if I stall. Continuing AUTH-14.

The agent's first response is grounded in its board activity (AUTH-11 through AUTH-14) and its recent tool calls (writing the mock), not in the original "write tests for auth" prompt from hours earlier.

Companion chat and standing approvals

Companion chat pairs well with owner alerts and standing approvals. A common workflow:

  1. An agent hits a decision point that exceeds its standing approval limit and sends an owner alert.
  2. You get a push notification on your phone, open the iOS app, and tap into companion chat.
  3. You ask "what's the decision?" in plain language — the companion synthesizes the context from the activity log.
  4. You type a one-line approval or rejection. The agent receives it and continues.

This is faster than reading raw terminal output and more reliable than trying to infer the decision from a one-line alert message. The companion chat gives you enough context to decide without requiring you to catch up on the full session history.

Frequently asked questions

What is the amux companion chat?

Companion chat is a natural-language interface for talking to any running amux agent. It appears as a chat panel in the iOS app and the web dashboard. The companion loads the agent's last 15 recorded actions automatically, so you can ask "what are you working on?" and get a specific answer rather than having to parse raw terminal output.

What is the agent activity log?

Every prompt sent to a session, every board mutation, every peer message received, and every context compaction event is recorded in amux's command history. The companion chat pulls the 15 most recent entries from this log into its context before answering. This is what makes the answers grounded — the companion is not guessing based on the original task description, it is summarizing what the agent actually did.

Can I redirect an agent from my phone?

Yes. Messages typed in companion chat are delivered to the agent's session as new prompts via the same mechanism as amux send. The agent receives the message at its next turn boundary and responds. You can correct, redirect, or ask for a status summary without SSHing into your server or opening a terminal.

How is companion chat different from just reading terminal output?

Terminal output is a raw character stream: ANSI escape codes, interleaved JSON tool calls, model thinking blocks, and progress bars all mixed together. On a phone screen it is nearly unreadable. Companion chat is a mediated interface: you ask a question in plain English, the companion synthesizes the answer from the structured activity log, and you get a sentence. For "is it stuck?" or "what did it finish?" checks while away from your desk, companion is the right surface. For debugging a specific tool call failure, peek at the terminal.

Does companion chat work for all agent runtimes?

Yes. Companion chat is a feature of the amux orchestrator layer, not the underlying AI runtime. It works equally for Claude Code, Codex CLI, and Gemini CLI sessions. The activity log captures amux-level events regardless of which runtime the session runs.

Does the companion know about my codebase?

The companion's context is the agent's activity log — prompts, board events, and session metadata. It does not have direct access to your codebase or the agent's full context window. For questions about specific code the agent produced, ask the agent directly ("show me what you wrote for AUTH-14") rather than asking the companion to summarize code it has not seen.
