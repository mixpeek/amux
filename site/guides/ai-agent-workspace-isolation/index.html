AI Agent Workspace Isolation

Run 10+ parallel agents on the same codebase without file conflicts. Each agent gets its own git worktree and TMPDIR. Published September 2026.

The most common failure mode when running multiple coding agents in parallel: Agent A reads a file to understand how something works. Agent B has been editing that same file for the past ten minutes. Agent A reads B's half-finished draft, draws the wrong conclusion, and writes a commit built on a broken premise. Nothing fails loudly — the commit looks clean, tests pass locally, and the mistake surfaces three days later in code review.

Workspace isolation prevents this entirely. Each agent gets its own git worktree — a dedicated directory with its own index and working tree. Agents share history (so commits accumulate correctly) but never see each other's uncommitted files. Enable it with one environment variable.

The shared-checkout problem in detail

When parallel agents share a single git checkout, four classes of conflict recur:

Conflict class What happens Why it's hard to catch
Read-race on shared files Agent reads a peer's half-finished edit, concludes wrong behavior, commits bad code No error; the read succeeds silently on corrupted state
Test-red from peer's draft Agent runs tests; a peer's unstaged edit breaks a test in a file the agent never touched Test failure looks like the agent's own regression
Commit sweep Agent commits by pathspec; silently includes a peer's unstaged hunks in a file they both edited The commit diff looks correct; peer's work appears under the wrong author
TMPDIR collision Two agents write to the same generic temp path; second write silently overwrites first No error; data loss is silent

On a shared checkout with 10+ agents running overnight, all four classes occur routinely. The damage is not always recoverable — a commit that swept a peer's work is already in history, and TMPDIR overwrites leave no artifact.

How workspace isolation works

When AMUX_WORKSPACE_ISOLATION=1 is set, amux calls git worktree add for each worker at launch time. The worktree gets its own directory under <project-dir>/.worktrees/<session-name>/, its own git index, and its own TMPDIR under ~/.amux/tmp/<session-name>/.

Agents share the same git object store and the same committed history. Commits from any worktree accumulate on the same branch. But the working tree — the files that exist on disk and the staged state — is private to each agent. A file that Agent B is halfway through editing simply does not exist in Agent A's directory.

Enabling workspace isolation

Step 1: Install or update amux

curl -fsSL https://amux.io/install.sh | bash
brew upgrade mixpeek/tap/amux

Workspace isolation requires amux v0.9.97 or later. Check your version: amux --version.

Step 2: Add the environment variable

# Add to ~/.amux/server.env
AMUX_WORKSPACE_ISOLATION=1

This is a server-level setting that applies to all workers on this amux instance. After editing server.env, restart amux: amux restart (or the equivalent launchd/systemd reload for your setup).

Step 3: Register your project

amux register myproject --dir ~/Dev/myproject

The registered directory is the base; worktrees are created under its .worktrees/ subdirectory automatically.

Step 4: Launch workers

amux start myproject

Each worker launched against this project gets its own worktree. The dashboard shows each worker's cwd as its dedicated worktree path, not the shared project root.

Step 5: Verify isolation

curl -sk $AMUX_URL/api/sessions | python3 -c "
import json, sys
for s in json.load(sys.stdin):
    print(s['name'], s.get('cwd', '(no cwd)'))"

Each session should show a path ending in .worktrees/<session-name>. If you see the shared project root, the isolation is not active — check that server.env was saved and amux was restarted.

Worktree lifecycle

Worktrees are created when a worker launches and cleaned up when the worker session ends cleanly. If a worker crashes, the worktree persists for inspection — you can check what it was working on, read its partial commits, and decide whether to cherry-pick or discard them before removing the worktree with git worktree remove <path>.

The .worktrees/ directory is gitignored by default — amux adds it to .git/info/exclude on the first worktree creation so it does not appear in git status of the main checkout.

Combining isolation with vault secrets

Workspace isolation pairs with the vault secrets feature (AMUX-5375, September 2026). Each worker's isolated environment gets its scoped secrets injected as environment variables at launch — API keys, database credentials, and OAuth tokens are agent-specific and never appear in the shared filesystem. The combination means agents are isolated both in filesystem state and in credential access.

Isolation and the approval memory system

The approval memory system (September 2026) auto-saves owner approvals as standing rules. With workspace isolation, those approvals still apply fleet-wide — an approval saved from one worker's context applies to the same action in any other worker. Isolation is filesystem-level; the approval layer is fleet-level. Both can be active simultaneously.

Performance considerations

Creating a git worktree is fast — typically under 200 milliseconds on a standard SSD. The worktree itself adds no duplication of git history, only a checkout of the working tree files. On a large monorepo (50 GB+), the initial checkout takes longer, but amux uses --no-checkout for the worktree creation and then checks out only the paths the agent will actually read, keeping the footprint proportional to actual usage rather than full tree size.

Workspace isolation vs other conflict-avoidance strategies

Strategy How it works What it misses
Pathspec commits Commit only named paths, not the whole index Still sweeps a peer's unstaged hunks in a co-edited file
git status guards Check for dirty files before acting Identifies a conflict exists; does not prevent the read-race that corrupts reasoning
Branch-per-agent strategy Each agent commits to its own branch, merged later Complex merge topology at scale; agents still share a working tree mid-session
Workspace isolation (amux) Each agent gets its own worktree, index, and TMPDIR at the filesystem level Requires git repo; worktrees accumulate on crashes until manually cleaned

Run parallel agents without conflicts

Workspace isolation is one environment variable. amux is open source, single Rust binary, MIT licensed. Each agent gets a clean slate every time.

curl -fsSL https://amux.io/install.sh | bash
echo 'AMUX_WORKSPACE_ISOLATION=1' >> ~/.amux/server.env
amux restart
