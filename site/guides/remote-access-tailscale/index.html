Remote Access with Tailscale: Your Self-Hosted amux on iPhone, iPad and Mac

Reach your amux server from any device with a real HTTPS certificate. No public ports, no SSH exposure, no port forwarding.

amux (amux.io, github.com/mixpeek/amux) is a self-hosted control plane for AI coding agents: Claude Code, Codex, Gemini CLI, OpenCode and Ollama models running side by side on your own Mac or Linux machine. Tailscale is the simplest way to reach that machine from your phone. This guide takes about 15 minutes and ends with https://<host>.<tailnet>.ts.net:8824 opening on your iPhone with a valid padlock.

How it works

amux always serves HTTPS on port 8824. On first start it creates a self-signed certificate in ~/.amux/tls, which is fine for https://localhost:8824 but shows a warning everywhere else. Tailscale can issue a Let's Encrypt certificate for your machine's MagicDNS name. You write that certificate into ~/.amux/tls yourself with tailscale cert. When amux starts, it looks for a <name>.ts.net.crt file with a matching .key and serves it to any client that connects by that exact name. Clients that connect by localhost or by IP address still get the self-signed certificate.

amux does not request or renew the Tailscale certificate for you. That part is the tailscale cert command below.

Before you start

  • amux installed and running on a Mac or Linux machine (curl -fsSL https://amux.io/install.sh | bash, then open https://localhost:8824).
  • A Tailscale account. The free personal plan is enough.
  • Admin access to your tailnet's admin console, to turn on HTTPS certificates.

Setup

1. Install Tailscale on the server and your devices

Install Tailscale on the machine that runs amux and on every device you want to use: iPhone, iPad, laptop. Sign in to the same tailnet on each one. Note the server's MagicDNS name. It has the form <host>.<tailnet>.ts.net, for example desktop.tail5ce8f5.ts.net. You can read it in the Tailscale app, in the admin console's Machines page, or on the server with:

tailscale status --json | grep DNSName

2. Enable HTTPS certificates in the Tailscale admin console

Open the Tailscale admin console, go to DNS, make sure MagicDNS is on, and enable HTTPS Certificates. Without this, tailscale cert refuses to issue a certificate.

3. Issue the certificate into ~/.amux/tls

On the amux server, replace <host>.<tailnet> with your own name and run:

tailscale cert \
  --cert-file ~/.amux/tls/<host>.<tailnet>.ts.net.crt \
  --key-file  ~/.amux/tls/<host>.<tailnet>.ts.net.key \
  <host>.<tailnet>.ts.net

The file names matter. amux reads the host name from the file name, so the part before .crt must be exactly the name you will type in the browser. Keep one Tailscale certificate pair in that folder. If you set AMUX_HOME, the folder is $AMUX_HOME/tls instead.

On Linux, if tailscale cert says access is denied, allow your user to drive Tailscale once as root: sudo tailscale set --operator=$USER.

4. Restart amux

amux reads certificates when it starts, so restart it to pick up the new files:

# macOS
launchctl kickstart -k gui/$(id -u)/com.amux.server-rs

# Linux
systemctl --user restart amux-server

5. Open the dashboard on any tailnet device

On your phone or laptop, with Tailscale connected, open:

https://<host>.<tailnet>.ts.net:8824

The browser should show a valid padlock. A trusted certificate also lets the dashboard register its service worker, which the installable PWA needs. Sign in with the token from ~/.amux/auth_token on the server, or turn on the owner sign-in described below.

6. Add the server to the iPhone, iPad or Mac app

  • iPhone and iPad: install amux from the App Store (one app for both), choose self-hosted, and enter https://<host>.<tailnet>.ts.net:8824.
  • Mac: download Amux-macOS.dmg (macOS 12+, Apple silicon and Intel) and add the same URL as a connection. The app is not notarized yet, so the first open needs System Settings, Privacy & Security, Open Anyway.
  • Android or any browser: open the URL and choose Install app or Add to Home Screen to install the PWA.

See Manage AI coding agents from your iPhone or iPad for what you can do once connected.

7. Schedule renewal every 90 days

Certificates from tailscale cert expire after 90 days. Re-run the command and restart amux before then. The amux scheduler can do it with a shell schedule, which runs the command directly with no agent and no model cost. On macOS, from the server:

H=<host>.<tailnet>.ts.net
curl -sk -X POST -H 'Content-Type: application/json' https://localhost:8824/api/schedules -d "{
  \"title\": \"Renew Tailscale cert\",
  \"kind\": \"shell\",
  \"schedule_expr\": \"monthly on 1 at 4am\",
  \"command\": \"tailscale cert --cert-file ~/.amux/tls/$H.crt --key-file ~/.amux/tls/$H.key $H && launchctl kickstart -k gui/\$(id -u)/com.amux.server-rs\"
}"

On Linux, swap the last command for systemctl --user restart amux-server. Requests from localhost need no token. Pick a quiet hour, since the restart briefly disconnects open dashboards.

Optional: sign in by Tailscale identity

By default every device signs in with the bearer token in ~/.amux/auth_token. Two server settings let Tailscale's own identity do it instead. Both are off unless set, and both go in ~/.amux/server.env.

SettingWhat it doesNever qualifies
AMUX_TRUST_TAILNET_OWNER=1Devices that the local Tailscale daemon identifies as the server owner's own sign in automatically. The connecting address must match the daemon's record for that device. amux then sets its usual Secure, HttpOnly owner session cookie; the owner key never goes into a link or browser storage.Forwarded headers, LAN addresses, other tailnet users, tagged devices and expired devices.
AMUX_TAILNET_MEMBER_AUTH=1An invited member signs in by Tailscale login alone, when that login equals their accepted member email, and gets that member's scope. No cookie is minted: the daemon's answer is cached per address for 60 seconds, so removing someone from the tailnet revokes them within a minute, and deleting the member revokes them at once.Tagged devices, expired devices and the server owner's own devices.

If the Tailscale identity check is unavailable, ordinary token sign-in keeps working.

amux Cloud: join your own tailnet

An amux Cloud server (your own dedicated server at yourname.amux.io) already has a public HTTPS address. You can also put it on your tailnet: open Settings, then Your tailnet, and choose Add to my tailnet. Approve the device with the Tailscale login link, or paste an auth key to join without the link. Once it is on the tailnet, amux runs tailscale serve, which publishes the server at https://<host>.<tailnet>.ts.net with Tailscale's own certificate, so you skip steps 3, 4 and 7. Nothing about your tailnet passes through amux Cloud. Only the server's owner can change this setting.

Why no public ports or SSH are needed

  • Tailscale builds an encrypted WireGuard network between your own devices, so the server needs no open inbound port on your router or cloud firewall.
  • The dashboard, the apps and the REST API all use the same HTTPS address, so there is no SSH tunnel to keep alive on your phone.
  • Port 8824 stays private to your tailnet. Never expose it to the public internet.
  • amux still checks its bearer token (or the Tailscale identity settings above) and refuses cross-site requests, so tailnet membership alone does not grant access.

Troubleshooting

The browser still shows a certificate warning

  • Check the file names in ~/.amux/tls. They must be <host>.<tailnet>.ts.net.crt and <host>.<tailnet>.ts.net.key, spelled exactly like the name you open.
  • Open the full MagicDNS name. https://100.x.y.z:8824 or the short host name gets the self-signed certificate by design.
  • Restart amux after writing or renewing the files. Certificates are read at startup.
  • Check that the certificate has not expired: openssl x509 -enddate -noout -in ~/.amux/tls/<host>.<tailnet>.ts.net.crt.

tailscale cert fails

  • HTTPS Certificates is off in the admin console's DNS page. Turn it on and retry.
  • MagicDNS is off, so the machine has no ts.net name. Turn it on.
  • On Linux, "access denied" means your user cannot drive tailscaled. Run sudo tailscale set --operator=$USER once.

The name does not resolve on my phone

  • Check that Tailscale is connected on the phone and that it is signed in to the same tailnet as the server.
  • Use the exact name from tailscale status. The tailnet part (for example tail5ce8f5) is specific to your tailnet.

FAQ

Does amux create the Tailscale certificate for me?

No. You run tailscale cert yourself and write the files into ~/.amux/tls. When amux starts, it finds any <name>.ts.net.crt and matching .key in that folder and serves that certificate to clients that connect by that name. Everything else, including localhost, keeps amux's own self-signed certificate.

Do I need to open ports on my router or expose SSH?

No. Tailscale connects your devices directly over an encrypted WireGuard network, so port 8824 is only reachable from devices in your tailnet. Never expose port 8824 to the public internet.

Why does my browser still show a certificate warning?

Usually the filename does not match the name you typed. The file must be named exactly <host>.<tailnet>.ts.net.crt (with a matching .key) and you must open that same full name, not the 100.x address or the short host name. Then restart amux, because certificates are read at startup.

How often do I need to renew the certificate?

Certificates from tailscale cert expire after 90 days. Re-run the command and restart amux before then. A monthly amux schedule with kind shell does this without using an agent.

Can I sign in from my phone without pasting the token?

Yes, if you set AMUX_TRUST_TAILNET_OWNER=1 on the server. Devices that the local Tailscale daemon reports as your own (same Tailscale user, untagged, unexpired) then sign in automatically. Forwarded headers, LAN addresses, other tailnet users, tagged devices and expired devices never qualify.

Can teammates sign in with their Tailscale login?

Yes, with AMUX_TAILNET_MEMBER_AUTH=1. An invited member whose Tailscale login matches their accepted member email signs in by that login alone and gets that member's scope. Removing them from the tailnet revokes access within a minute; deleting the member revokes it at once.

Does this work with amux Cloud?

Yes. An amux Cloud server can join your own tailnet from the dashboard (Settings, Your tailnet) with a login link or an auth key. It then publishes itself with tailscale serve at https://<host>.<tailnet>.ts.net. Nothing about your tailnet passes through amux Cloud.
