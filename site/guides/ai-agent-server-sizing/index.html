AI Agent Server Sizing Guide

August 2026 — RAM, CPU, and disk requirements for 5 to 50+ parallel Claude Code, Codex, or Gemini CLI agents, plus amux OOM protection.

Run your AI engineering team overnight — with built-in OOM protection
amux refuses to start new agents when your server is running low on memory — so a runaway fleet can't crash your machine at 3am. Open source, MIT licensed, 374+ stars.
View amux on GitHub ★

Running a fleet of AI coding agents overnight is practical on almost any modern server — but getting the sizing right prevents the 3am crash that wipes out your agents' work. This guide covers the numbers you need: how much RAM per agent, when to move from your laptop to a cloud VM, and how amux's new OOM protection prevents resource exhaustion from taking down your fleet.

The Short Answer: RAM is the Constraint

CPU is rarely the bottleneck when running AI coding agents. Agents spend the vast majority of their time waiting for API responses from Anthropic, OpenAI, or Google — not doing compute work on your server. The real constraints are:

  • RAM — each agent process consumes 300-500 MB. This is the primary scaling constraint.
  • Disk I/O — agents write frequently to the codebase. SSD matters more than total disk size.
  • Network — API calls are the critical path. Low-latency internet access to the provider matters.

CPU: budget 0.1-0.2 vCPU per active agent. 4 vCPUs handles 20-40 agents with headroom.

amux OOM Protection (August 2026)

The most common fleet failure mode is starting too many agents: you queue 30 tasks, start them all at once, and at 2am your server runs out of RAM. Every agent starts swapping, they all slow to a crawl, and some crash with context errors.

amux now prevents this. Before admitting each new worker, the server checks available memory headroom. If RAM is critically low, the server refuses to start the new session and surfaces the refusal reason in the dashboard and via GET /api/health/invariants. Existing agents continue running — only new session creation is blocked until memory frees up.

# Check fleet health including memory headroom
curl -sk https://localhost:8824/api/health/invariants | python3 -c "
import json, sys
for inv in json.load(sys.stdin)['failing']:
    print('FAIL:', inv['name'], '—', inv['message'])
"

The OOM gate fires automatically with no configuration required. If you want to override it for a specific session (not recommended), set AMUX_SKIP_OOM_GATE=1 in the session environment.

Disk Requirements

Agents running on the same codebase share a single git checkout, so disk usage scales with the codebase rather than agent count. Key considerations:

  • Codebase size — most repos are 100 MB-5 GB including git history. SSD is strongly recommended; HDD latency causes noticeable slowdown when agents write frequently.
  • Git worktrees — for true parallel isolation (agents working on different branches simultaneously), each worktree is a full working tree checkout. Budget 500 MB-2 GB per worktree for typical monorepos. See the git worktree isolation guide.
  • Agent scratch space — amux agents can write intermediate files to a configurable scratch directory. Budget 1-5 GB for a 50-agent fleet with heavy tool use.
  • Disk watchdog — amux monitors disk usage and surfaces alerts in the dashboard and invariants endpoint when the agent scratch root is filling up.

Running Agents Remotely

If your local machine is underpowered, you don't need to run amux on it. amux-remote (shipped August 2026) lets your local amux CLI connect to a remote amux server over Tailscale or SSH. You manage the fleet from your laptop or phone while all agents run on a more powerful remote machine.

Frequently Asked Questions

How much RAM do I need to run AI coding agents?

Budget 300-500 MB RAM per agent plus 1-2 GB for the OS and amux dashboard. For 10 agents: 6-8 GB. For 50 agents: 26-28 GB minimum. A MacBook Pro with 16 GB handles 20-25 agents reliably; a 32 GB model handles 50+. For larger fleets, use a dedicated cloud VM.

What happens when my server runs out of RAM while running AI agents?

Without protection, the OS swaps to disk, agents slow dramatically, and eventually crash. amux (August 2026) adds OOM protection: new worker admission is refused when memory headroom is critically low. Existing agents keep running. The refusal reason appears in the dashboard and in GET /api/health/invariants.

Can I run AI coding agents on a MacBook?

Yes. A MacBook Pro with 16 GB RAM reliably runs 20-25 parallel agents. A 32 GB MacBook Pro handles 50+. amux is a single Rust binary with no external dependencies — it runs identically on macOS and Linux. For overnight runs where you want your laptop free, connect to a remote server via amux-remote instead.

What cloud VM should I use for 10-50 AI agents?

For 10-25 agents: Hetzner CX32 (8 GB, 4 vCPU, ~€0.13/hr) offers the best price/performance outside AWS. For 50 agents: Hetzner CX42 (16 GB) or AWS c6a.4xlarge (32 GB). CPU is rarely the bottleneck — agents wait on API responses. Prioritize RAM and SSD storage over CPU core count.

How much disk space do AI agents need?

Disk usage is dominated by the codebase size, not agent count — all agents on the same task share one git checkout. For git worktree isolation (parallel branch work), budget 500 MB-2 GB per worktree for a typical monorepo. Use SSD: agents write frequently and HDD latency compounds across 20+ simultaneous writers.

Does amux protect against out-of-memory crashes?

Yes. amux (August 2026) checks available memory headroom before starting each new worker. If RAM is critically low, new session creation is refused and the reason surfaces in the dashboard and invariants API. Existing agents are never stopped by this gate — only new sessions are blocked until memory frees up. No configuration required.
