Search AI Agent History

Find what any agent did, said, or encountered — across all sessions, instantly.

Published: October 13, 2026

Quick answer: amux indexes session messages, terminal logs, and chat transcripts with FTS5 full-text search. Open the search panel (Cmd+K), type a keyword, and get ranked results across every session with jump-to-context links. Also available via REST API: GET $AMUX_URL/api/search?q=your-query.

The problem with agent output

One Claude Code agent running for a few hours generates thousands of lines of terminal output. A fleet of 10 agents running overnight generates tens of thousands. When something goes wrong at 3am — a build failure, a test that flipped, an unexpected API error — the only way to find it is to open each session's peek panel and scroll.

Scrolling works when you know which session failed and roughly when. It breaks down when the failure could be in any of 10 sessions, or when you need to trace a decision an agent made 6 hours ago, or when you're on your phone trying to do a quick check after waking up.

amux ships FTS5 full-text search across all session messages, terminal logs, and chat transcripts. One search field. All sessions. Instant results with context.

What gets indexed

The search index covers three sources:

  • Session messages — every message sent to and received from agents via the amux messaging API (POST /api/sessions/NAME/send), including inter-agent messages and steering instructions
  • Terminal logs — the raw scrollback from each session's tmux pane: compiler output, test results, shell commands, agent responses in the terminal, stack traces
  • Chat transcripts — the full conversation history from each session's companion chat interface, structured turn by turn

All three are searched simultaneously by default. Use the type filter to narrow to just one source when you know where the information lives.

How to search from the dashboard

  1. Press Cmd+K (Mac) or Ctrl+K (Windows/Linux) from anywhere in the dashboard, or click the search icon in the top navigation
  2. Type your query — results appear as you type, ranked by relevance and recency
  3. Use the Session filter dropdown to narrow results to a specific worker
  4. Use the Time filter to search within the last hour, 24 hours, 7 days, or a custom range
  5. Click any result to open that session's peek panel at the matching line, with surrounding context visible

Searching from the REST API

The search endpoint is available to any session or script running on the same machine:

# Search all sessions for an error message
curl -sk "$AMUX_URL/api/search?q=ENOENT&limit=20"

# Search a specific session's history
curl -sk "$AMUX_URL/api/search?q=migration+failed&session=backend-agent&limit=10"

# Search only terminal logs (not messages or transcripts)
curl -sk "$AMUX_URL/api/search?q=undefined+symbol&type=logs&limit=20"

# Search within the last 24 hours
curl -sk "$AMUX_URL/api/search?q=test+failure&since_h=24"

Each result includes: the session name, source type (message/log/transcript), timestamp, the matching line, and N lines of surrounding context. The context window is configurable via the context parameter (default: 3 lines before and after).

Common search patterns

Post-overnight review

Wake up, open amux on your phone, and search "error" or "failed" or "could not" to immediately surface what went wrong across all overnight sessions — without opening each one manually. Sort by recency to see the most recent failure first.

Tracing a file across agents

When multiple agents work on the same codebase, it's common for one agent to modify a file and another to encounter the effects later. Search the file path (src/auth/middleware.ts) to see every agent that mentioned it, in chronological order.

Finding a decision

Agents document their reasoning in chat. Search for "decided" or "because" or "instead" to surface decision points — useful when reviewing whether an agent's approach was reasonable before reviewing its output.

Verifying work without opening peek

Before marking a task done, search the task title to confirm the relevant agent mentioned completing it, which file it touched, and what tests it ran — without scrolling the full terminal.

Cross-session dependency check

An orchestrator agent checking whether a worker completed a specific module can search instead of peeking: GET /api/search?q="auth+module+complete"&session=backend-agent. A non-empty result confirms the work was done and the agent announced it.

Search from your phone

The search panel is available in the amux PWA and native iOS app. On mobile:

  • Tap the search icon in the header to open a full-screen search modal
  • Results list below the input with session name, timestamp, and matching text
  • Tap any result to jump to that session's peek panel at the matching line
  • The time filter defaults to "last 24 hours" on mobile for faster results

The most useful phone pattern: after a morning notification that an agent finished, search the session name plus "done" or "complete" to verify the work summary without reading the full transcript.

How the index works

amux uses SQLite's FTS5 virtual table for the search index. FTS5 uses a trigram-based index optimized for prefix and phrase queries. Indexing happens asynchronously in a background job — new session output is indexed within a few seconds of being written.

The index reports its own lag: GET /api/search?q=&stats=1 returns index_lag_seconds per session, so you know whether a very recent event might not be indexed yet. On a typical fleet with 10 active sessions, lag is under 5 seconds.

Index storage is compact. A busy agent session running for 30 days typically adds 30–60 MB to the SQLite database. The full search database for a 25-session fleet over 30 days fits comfortably under 2 GB on the host machine's disk.

Frequently Asked Questions

Can I search what a Claude Code agent did?

Yes. amux indexes all session messages, terminal logs, and chat transcripts with FTS5 full-text search. Type any keyword in the dashboard's search panel — an error message, a filename, a function name — and amux returns matching lines across every session with surrounding context and a link to jump to that exact point in the peek panel.

What does the search cover?

Three sources: session messages (everything sent and received via the messaging API), terminal logs (raw tmux scrollback including compiler output, test results, and shell commands), and chat transcripts (companion chat conversation history). All three are searched together by default; the type filter narrows to one source.

How far back does the history go?

As long as the session exists. Active sessions accumulate history continuously — a session running for weeks is fully searchable. When a session is removed, its index entries are removed too. A busy 30-day session adds roughly 30–60 MB to the index.

Can agents search each other's history?

Yes, via the REST API. Any session that can make an HTTP call can query GET $AMUX_URL/api/search?q=query&session=other-session. This lets an orchestrator agent verify that a worker completed a specific task without needing to peek at raw terminal output.

Is there a command-line interface for search?

Yes: amux search "your query" searches all sessions and prints results to stdout. Add --session backend-agent to filter by session, --since 24h for a time filter, and --type logs or --type messages to filter by source. Results include session name, timestamp, and the matching line with context.
