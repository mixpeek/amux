Run AI Coding Agents with Ollama
Local LLM Agents, No API Key Required (2026)

To run AI coding agents with Ollama and amux: install Ollama, pull qwen3.8:27b, then create a new amux worker and select Ollama as the provider. No API key, no usage bill, and no code leaves your machine. amux supports Ollama alongside Claude Code and Codex so you can mix local and cloud agents from one dashboard.

Published August 2026. Ollama provider shipped August 2026 (commit aa436ca)

Why use Ollama for AI coding agents?

Three reasons drive most teams to Ollama:

  • Privacy. Your source code, prompts, and outputs never touch an external server. This matters for proprietary codebases, client work under NDA, or anything that touches regulated data (HIPAA, SOC 2, PCI).
  • Cost. At scale, per-token cloud costs add up quickly. A local GPU running continuously has a fixed cost, which can be substantially cheaper than API billing for high-volume coding tasks.
  • Air-gapped environments. Defense, financial infrastructure, and some enterprise environments prohibit outbound API calls from development machines. Ollama lets you run capable coding agents entirely offline.

amux added first-class Ollama support in August 2026 (commit aa436ca), defaulting to qwen3.8:27b as the local model. You can run it alongside cloud-backed workers from the same dashboard, which means you can route sensitive tasks locally and complex tasks to Claude Sonnet without switching tools.

Setup: Ollama + amux in 5 steps

# 1. Install amux (if you haven't already) curl -sSL https://amux.io/install.sh | bash # 2. Install Ollama from ollama.com, then start the server ollama serve # 3. Pull qwen3.8:27b (approx 17GB, ~5 min on fast internet) ollama pull qwen3.8:27b # 4. Open the amux dashboard open https://localhost:8824 # 5. Click + → select Ollama as provider → name the worker → launch # amux connects to http://localhost:11434 automatically

That's it. The new worker appears in your dashboard alongside any existing Claude Code or Codex workers. The board, messages, Simple tab, and phone monitoring all work exactly the same way.

How amux connects to Ollama

Ollama runs a local HTTP server at http://localhost:11434 that speaks a standardized completion API. amux talks to it the same way it talks to the Anthropic or OpenAI endpoints: it sends a prompt, receives a streamed response, and surfaces the output in the worker's terminal and message history.

The key difference from cloud providers is that authentication is local. Ollama requires no API key for localhost access, so amux skips the credential prompt entirely when you select the Ollama provider. The model name (qwen3.8:27b by default) is the only setting you need to configure.

amux does not relay traffic through its cloud infrastructure when using Ollama. The worker runs on your machine, Ollama runs on your machine, and all inference stays local. The amux dashboard itself can optionally be accessed remotely via Tailscale, but the model inference never leaves your network.

When to use local agents

Air-gapped development

For environments where outbound API calls are prohibited or network access is restricted, Ollama lets you run a capable coding agent with no external dependencies. After the initial model pull, everything runs offline. Use amux to orchestrate multiple Ollama workers on separate codebases, with the board tracking task status across all of them.

Cost reduction at scale

A single NVIDIA RTX 4090 running qwen3.8:27b can handle many concurrent coding tasks with no per-token billing. If your team is running dozens of amux workers per day on routine tasks (test generation, boilerplate, documentation), local inference can reduce monthly API costs significantly. The mixed provider model in amux makes it easy to route accordingly: Ollama for the high-volume routine work, Claude for the tasks that need its edge.

Privacy-sensitive codebases

Client code under NDA, internal financial models, unreleased product code: these are the scenarios where sending source to a cloud model is a policy problem, not just a preference. With the Ollama provider, your prompts and your code never leave your development machine. amux stores agent history in a local SQLite database, so the audit trail stays local too.

Mixed fleet: local for sensitive, cloud for complex

The most practical pattern for most teams is a mixed fleet. Run Ollama workers for sensitive files, tests, and documentation. Run Claude Code workers for the tasks that need deep reasoning: multi-file refactors, architecture decisions, complex debugging. amux groups let you organize workers by project or by provider, and the board shows status across all of them from one view.

Ollama vs Claude API: honest comparison

This is not a contest. The right choice depends on what you're optimizing for.

Privacy Code never leaves your machine Sent to Anthropic servers (standard API terms)

Internet required No (after initial pull) Yes, always

Context window Varies by model; typically 32K–128K tokens 200K tokens (Claude 3.5+)

Tradeoffs to know before you commit

Where local wins

  • Proprietary or regulated code
  • High-volume routine tasks (tests, docs, boilerplate)
  • Air-gapped or restricted networks
  • Teams with strong on-prem GPU capacity
  • Long-running agents where API costs accumulate

Where cloud wins

  • Complex multi-file reasoning tasks
  • Large context windows (200K+ tokens)
  • Teams without capable GPU hardware
  • Fastest possible inference speed
  • Frontier model quality on hard problems

The honest summary: qwen3.8:27b is a capable model for coding, but it is not Claude Sonnet. For straightforward, well-scoped tasks it delivers good results at zero ongoing cost. For the hardest reasoning tasks, cloud models still have a meaningful edge. Most teams find the right answer is mixing both.

Frequently asked questions

Can I run AI coding agents without an API key?

Yes. When you select Ollama as the provider in amux, no API key prompt appears. amux talks directly to the Ollama server running on your machine at http://localhost:11434. The default model is qwen3.8:27b; pull it with ollama pull qwen3.8:27b.

What hardware do I need to run qwen3.8:27b locally?

An NVIDIA RTX 3080 (10GB VRAM) runs the model with 4-bit quantization at reasonable speed for interactive coding tasks. RTX 4090 or an A100 is faster. Apple Silicon Macs with 32GB unified memory (M2 Pro or later) work well via Metal. CPU-only inference is possible but very slow for interactive use.

Does my code leave my machine when I use Ollama with amux?

No. With the Ollama provider, all inference runs on your hardware. amux communicates with Ollama over localhost only. Your code, prompts, and responses stay on your machine. amux stores agent history in a local SQLite database at ~/.amux/amux.db.

Can I mix Ollama and cloud agents in the same amux dashboard?

Yes. Provider is a per-worker setting. Create one worker with Ollama for sensitive code, another with Claude Code for complex reasoning, and a third with Codex CLI if you have an OpenAI key. All workers appear in the same dashboard, share the same board, and are all reachable from the amux iOS app.

Is qwen3.8:27b good enough to replace Claude Sonnet for coding?

For routine code generation, test writing, documentation, and small refactors: yes, it holds up well. For complex multi-file reasoning, architectural decisions, or tasks requiring very large context windows, Claude Sonnet and Opus still have a clear edge. The practical approach is to use both: Ollama for privacy-sensitive and high-volume routine work, cloud models when you need the best output quality on hard problems.
