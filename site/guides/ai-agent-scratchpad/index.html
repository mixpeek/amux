AI Agent Scratchpad: Persistent Notes for Your Coding Agent Fleet

Updated October 2026

A persistent shared workspace your entire agent fleet can read and write — no token cost until an agent asks for it. Get amux on GitHub

Every AI coding agent fleet eventually needs a place to store things that do not fit inside a single agent's context window: architecture decisions, a running list of completed tasks, a file ownership map, a shared API reference. Injecting this into every agent's pinned notes wastes tokens. Leaving it in a one-off file with no access from the dashboard loses it.

amux ships a built-in scratchpad: a global markdown workspace in the dashboard backed by ~/.amux/scratchpad/. Every agent on the machine can read from or write to it. It persists across restarts. It costs zero tokens unless an agent explicitly asks to read a file.

What the scratchpad solves

When you run more than a handful of agents in parallel, three categories of information accumulate that have no good home:

  • Decisions and rationale — why the team chose one approach over another, which trade-offs were accepted, what was explicitly ruled out.
  • Coordination state — which agent owns which file, the current sprint priorities, a list of PRs waiting for review.
  • Reference documents — API contracts, schema definitions, vendor-specific quirks that multiple agents need to consult but do not need in memory every turn.

The scratchpad is the right place for all of these. Pinned notes are the right place for standing instructions that must be in context on every turn.

How the scratchpad works

The scratchpad tab appears in the amux dashboard's global tab bar. Clicking it opens a file browser rooted at ~/.amux/scratchpad/. The directory is created automatically the first time you visit the tab.

From the dashboard you can:

  • Create, browse, and edit markdown files and subdirectories
  • View a breadcrumb navigation path for nested directories
  • Sort files by name or modification date
  • Edit any text file with the same inline editor used in the rest of the dashboard

From an agent session, the path is just a regular filesystem path:

# an agent reads a reference doc
cat ~/.amux/scratchpad/api-contract.md

# an agent appends to a decision log
echo "2026-10-10: chose postgres over sqlite for volume reasons" >> ~/.amux/scratchpad/decisions.md

Scratchpad vs. pinned notes vs. amux memory

Feature Scratchpad Pinned notes amux memory
When content enters agent context On demand — only when agent reads the file Every session start On demand (Claude Code decides)
Token cost per session Zero unless agent reads it Proportional to note length, every time Proportional to memory size, on recall
Managed by You + agents via filesystem amux (amux pin set / get) Claude Code (saves memory automatically)
Scope All agents on the machine Global, group, or per-worker Per Claude Code session
Visible in dashboard Yes — Scratchpad tab with file browser Yes — Pins panel No — Claude Code internal
Persists across restarts Yes — plain files Yes — stored in amux DB Yes — stored in ~/.claude/
Best for Reference docs, coordination state, decision logs Standing instructions, rules every agent must follow Preferences, past-decision recall within one agent's history

Setting up a shared scratchpad for a fleet

A useful starting layout for a multi-agent engineering team:

~/.amux/scratchpad/
  architecture.md      # system design decisions
  file-ownership.md    # which agent owns which directory
  decisions.md         # running log of architectural choices
  current-sprint.md    # active tasks and their status
  api-reference.md     # vendor APIs, endpoints, auth patterns
  blockers.md          # anything waiting on a human decision

Tell agents about the scratchpad in a pinned note (this is the one case where a pinned note pointing to the scratchpad makes sense — the standing instruction is short, and the reference doc it points to is not injected automatically):

# in a pinned note (global scope)
Team reference docs live in ~/.amux/scratchpad/.
Read architecture.md before starting work on a new feature.
Append to decisions.md when you make a non-obvious architectural choice.
Read file-ownership.md before editing a file outside your assigned directory.

Combining scratchpad with workspace isolation

When workspace isolation is enabled (AMUX_WORKSPACE_ISOLATION=1), each agent gets its own git worktree at .worktrees/<worker>/. This means agents can stage and commit without interfering with each other, but they all still share the same ~/.amux/scratchpad/ directory on the host. The scratchpad is outside the git tree by design — it is a coordination layer, not a versioned artifact.

This combination works well for large teams where agents each own a domain:

  • Each agent writes a one-line status to ~/.amux/scratchpad/status/<worker-name>.md after finishing each task
  • An orchestrator agent reads all status files to check progress without needing to query the board
  • The human reviews the scratchpad daily to understand what the team decided without reading every commit

Scratchpad as an agent handoff mechanism

When you restart a long-running agent or fork a session to a fresh context, the agent loses its in-memory knowledge of what it did. The scratchpad solves this: the outgoing agent writes a handoff note before its context is compacted, and the incoming agent reads it on startup.

# agent writes at the end of a work session
cat >> ~/.amux/scratchpad/handoff.md <<'EOF'
## 2026-10-10 evening handoff

Completed: implemented the new /api/events endpoint (see PR #142).
In progress: the integration test in tests/test_events.py is failing on the
  date serialization case — I left a comment in the test with the suspected fix.
Next: after the PR merges, update the OpenAPI spec in docs/api.yaml.
Blocker: waiting for Ethan to approve the schema change in PR #141.
EOF

The next agent starts with:

Read ~/.amux/scratchpad/handoff.md and then continue the work described there.

How to set up the scratchpad

  1. Install amux — brew install mixpeek/amux/amux and run amux serve.
  2. Open the Scratchpad tab — click Scratchpad in the global tab bar. The directory ~/.amux/scratchpad/ is created automatically.
  3. Create your first note — click New File, name it context.md, and write the shared context your agents need.
  4. Reference it from agents — tell agents the path: cat ~/.amux/scratchpad/context.md. Or add a one-line pinned note pointing to the file.
  5. Build a handoff practice — ask long-running agents to append to ~/.amux/scratchpad/handoff.md before their session ends.

Frequently asked questions

What is the amux scratchpad?

The amux scratchpad is a global tab in the amux dashboard that provides a shared markdown file workspace at ~/.amux/scratchpad/. All agents on the machine can read from and write to scratchpad files. It is separate from each agent's context window — files only enter context when an agent explicitly reads them.

How is the scratchpad different from pinned notes?

Pinned notes are injected automatically into agent context at session start and consume tokens every time. The scratchpad is a passive file store — agents only read it when directed to. Use pinned notes for short standing instructions, and the scratchpad for larger reference documents that are read on demand.

Can multiple agents share the same scratchpad?

Yes. All agents on the same machine share ~/.amux/scratchpad/. One agent can write a decision log and another can read it. The scratchpad is outside the git worktree, so workspace isolation does not affect it.

Does the scratchpad survive an agent restart?

Yes. It is plain files on disk — it persists across agent restarts, context compactions, and amux server upgrades.

Can I use the scratchpad from my phone?

The scratchpad is accessible in the amux web dashboard from any browser. Visit your amux server URL from your phone's browser to read and edit scratchpad notes.

How does the scratchpad relate to amux memory?

amux memory (~/.claude/projects/*/memory/) is Claude Code's own mechanism for persisting facts between Claude Code sessions. The scratchpad is a separate, lighter-weight workspace managed by amux — use it for shared reference documents and coordination notes that are not specific to one agent's history.
