Claude Code Tutorial: Setup, Multi-Agent Workflows & Team Scaling (2026)

Everything you need to go from a single Claude Code session to running a full AI engineering team overnight — installation, first task, parallel agents, YOLO mode, mobile monitoring, and scaling with amux.

Updated September 2026 · 20 min read

Claude Code is Anthropic's autonomous coding agent. You give it a task in plain English and it reads your codebase, writes code, runs tests, and commits changes. One session handles one task at a time. But real engineering backlogs have dozens of tasks — and that is where amux comes in. This tutorial covers both: Claude Code itself and the infrastructure for running it as a team.

What is Claude Code?

Claude Code is Anthropic's command-line coding agent. Unlike IDE-based assistants that suggest completions, Claude Code operates as an autonomous agent: you describe what you want, and it reads your codebase, writes code, runs tests, and commits changes. It runs in your terminal, uses your local tools (git, npm, pip, etc.), and works with any language or framework.

One Claude Code session can hold an entire codebase in context, plan multi-step refactors, and execute them without constant hand-holding. The constraint is concurrency — by default, one session handles one task at a time. amux removes that constraint by running many sessions in parallel, each with its own git worktree and task, all monitored from a single dashboard you can check from your phone.

Prerequisites

  • Node.js 18+ — Claude Code is distributed as an npm package
  • An Anthropic API key — or a Claude Pro/Teams subscription
  • A terminal — macOS Terminal, iTerm2, Alacritty, Windows Terminal, or any Linux terminal
  • Git — Claude Code works best in git repositories where it can commit changes
  • tmux 3.2+ — required for amux (manages sessions in the background)

Step 1: Install Claude Code

Install Claude Code globally via npm:

npm install -g @anthropic-ai/claude-code

Verify the installation:

claude --version

If you're using the API directly, set your key:

export ANTHROPIC_API_KEY=sk-ant-...

For Claude Pro or Teams subscribers, run claude and follow the OAuth login flow — no API key required.

Step 2: Your first session

Navigate to any project directory and start Claude Code:

cd ~/Dev/my-project
claude

You'll see an interactive prompt. Start with an exploratory task:

> Explain the structure of this project and list the main entry points.

Claude Code reads your files, analyzes the codebase, and gives a structured overview. Then ask it to make a change:

> Add input validation to the signup form. Email must be valid, password must be 8+ chars.
> Write tests for the new validation logic.

Claude Code edits files, runs your test suite, and iterates until the tests pass. Every file change requires your approval by default — you see a diff and can accept or reject each edit.

Step 3: Understanding the approval flow

By default, Claude Code asks permission before every file write and command execution. This is the right default when you're learning. The approval categories:

ActionDefaultYOLO mode
Read filesAuto-approvedAuto-approved
Write/edit filesRequires approvalAuto-approved
Run shell commandsRequires approvalAuto-approved
Git operationsRequires approvalAuto-approved
Network requestsRequires approvalAuto-approved

Once you're comfortable, you can enable YOLO mode (Step 6) to let Claude Code run unattended — which is what makes overnight and parallel workflows possible.

Step 4: Context management

Claude Code has a context window limit. For large codebases, active management matters:

  • CLAUDE.md files — Place a CLAUDE.md in your project root with architecture notes, conventions, and instructions. Claude Code reads this automatically at the start of every session. The better your CLAUDE.md, the fewer tokens the agent spends exploring the codebase.
  • The /compact command — When your context gets full, type /compact to summarize the conversation and free up space. Do this proactively before hitting the limit.
  • Auto-compact — amux can trigger /compact automatically when context usage crosses a configurable threshold, so agents running overnight never stall from a full context window.
  • Focused prompts — Instead of "refactor the entire app," say "refactor the authentication module in src/auth/." Narrower scope means better results and lower token costs.
  • Git worktrees — Each Claude Code session should work on its own branch. Git worktrees let multiple sessions operate on the same repo without file conflicts.

A good CLAUDE.md:

# My Project

## Architecture
- Express.js API in src/api/
- React frontend in src/web/
- PostgreSQL database, migrations in db/migrations/

## Conventions
- Use TypeScript strict mode
- All API routes must have integration tests
- Commit messages follow conventional commits

## Current sprint
- AUTH-42: Add OAuth2 Google login
- API-99: Rate limiting on public endpoints

Step 5: Scale to a parallel AI engineering team with amux

A single Claude Code session is powerful. Real projects have dozens of tasks. amux runs many Claude Code sessions in parallel, each in its own tmux pane with its own git worktree, all visible from one dashboard. You manage the whole team from a browser — or your phone.

# Install amux (builds a Rust binary from source — takes 2-3 minutes first time)
git clone https://github.com/mixpeek/amux && cd amux && ./install.sh

# Register your project
amux register myproject --dir ~/Dev/myproject

# Start sessions
amux start myproject

Assign tasks to individual sessions:

# Session 1: working on auth
amux send auth "Implement Google OAuth2 login flow"

# Session 2: working on API
amux send api "Add rate limiting middleware to all public routes"

# Session 3: writing tests
amux send tests "Write integration tests for the payment module"

# Session 4: fixing a specific bug
amux send bugfix "Fix the race condition in the websocket handler (issue #142)"

All four agents work simultaneously. You monitor progress from the amux dashboard at https://localhost:8824 and merge completed branches when ready. The built-in kanban board tracks which tasks are in progress, done, or blocked.

Step 6: YOLO mode for unattended work

YOLO mode removes all approval prompts. Claude Code reads, writes, runs commands, and commits without asking. This is essential for parallel workflows — you cannot approve prompts for ten sessions at once — and for overnight runs where nobody is at the keyboard.

# Register with YOLO mode enabled
amux register myproject --dir ~/Dev/myproject --yolo

Safety considerations:

  • Always use git worktrees — each session works on its own branch, so a bad change cannot corrupt your main branch
  • Set up CI checks — require passing tests before merging any agent-generated branch
  • Review diffs before merging — YOLO mode means the agent runs unattended, but you still review the output
  • Use CLAUDE.md guardrails — add rules like "never delete migration files" or "never modify production config directly"

Step 7: Monitor from your phone

The amux dashboard is a mobile-optimized web app (PWA). Open it on your iPhone or Android phone and you get the same real-time view of your agents you have on a desktop browser.

amux serve
# Dashboard available at https://localhost:8824
# LAN access: https://192.168.x.x:8824

From the mobile dashboard you can:

  • See live output from all sessions, scrollable per-agent
  • Check which tasks are in progress, done, or blocked (kanban board)
  • Send messages or new prompts to any individual session
  • Get push notifications when an agent needs attention or finishes a task
  • Review and approve the kanban board's suggested next tasks

There is also a native iOS app on the App Store with a widget for your home screen.

Step 8: Multi-runtime teams (Claude Code + Codex + Gemini CLI)

amux works with Claude Code, OpenAI Codex CLI, and Google Gemini CLI. You can run a mixed fleet:

RuntimeBest foramux session type
Claude CodeComplex reasoning, large refactors, multi-step plansamux start --type claude
Codex CLISpeed-sensitive tasks, code generationamux start --type codex
Gemini CLIDocument-heavy tasks, large context windowsamux start --type gemini

All three show up on the same dashboard, share the same kanban board, and can coordinate through the same message bus. You can start with Claude Code and add Codex or Gemini sessions for specific workloads without changing your workflow.

Step 9: Advanced patterns

Task decomposition

Break large features into small, independently testable tasks. Instead of "build the payment system," create five tasks: "create the Stripe webhook handler," "build the subscription model," "add the billing page UI," "write payment integration tests," "add invoice PDF generation." Each task goes to a separate Claude Code session and they run simultaneously.

Agent-to-agent handoffs

Use the amux board to create dependency chains. An agent can mark its task done and create follow-up tasks for other agents. After the API session finishes the new endpoint, it adds a card to the board for the frontend session to build the UI — automatically, without you intervening.

Overnight runs

With YOLO mode, auto-compact, and amux's self-healing watchdog (which restarts crashed or stalled sessions), you can kick off a batch of tasks before you go to sleep and check results from your phone in the morning. The amux scheduler lets you queue tasks for specific times, like "run the full test suite at 3am and create cards for any failures."

Cost optimization

Running parallel sessions multiplies token spend. Ways to keep costs in check:

  • Use /compact aggressively — shorter contexts mean fewer input tokens on every subsequent message
  • Write detailed CLAUDE.md files so the agent does not spend tokens exploring your codebase on each task
  • Scope tasks tightly — "fix the bug in utils/date.ts line 42" is cheaper than "find and fix date bugs"
  • Use the amux cost monitor to track per-session and per-model spending in real time
  • Kill stuck sessions early from the dashboard — a session that is spinning costs the same as one making progress

Common pitfalls

  • Context overflow — If Claude Code starts forgetting earlier instructions, use /compact or start a new session. Do not keep pushing more content into a full context window; the quality degrades quickly.
  • Merge conflicts — When multiple agents edit similar files, conflicts happen. Assign agents to distinct parts of the codebase, or use a sequential workflow where one finishes before the next starts on related code.
  • Runaway commands — In YOLO mode, an agent can run an infinite loop or a destructive command. Use amux's session monitoring to catch this early, and add explicit guardrails in CLAUDE.md.
  • Stale branches — Agents work on worktree branches that drift from main. Rebase frequently, or use short-lived branches that merge quickly.
  • Idle agents — An agent that ends a turn with "I'll continue later" may not continue on its own. amux's idle detection re-prompts an agent once if it promised a next step but then went quiet, so stalled sessions do not pile up.
