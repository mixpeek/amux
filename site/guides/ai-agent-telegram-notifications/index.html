AI Agent Telegram Notifications

Get alerts from your coding agents, steer them by message, and route tasks to specific workers — all from Telegram on your phone.

amux connects your AI coding agent fleet to Telegram so you stay informed without polling a dashboard. Agents send status updates as they finish tasks. You reply to redirect work or approve a pull request. The connection goes both ways: Telegram is a read channel and a control channel at the same time. Setup takes under five minutes and requires no inbound port on your server.

Updated September 2026

Why Telegram for AI agent monitoring

Most developers monitor their agent fleet through a dashboard tab. That requires opening a browser, navigating to the right session, and actively checking for updates. Telegram flips this: your phone pings you the moment anything happens.

Three properties make Telegram a good fit for agent fleets specifically:

  • Push, not pull. You don't check Telegram. Telegram tells you when something happens. An agent that finishes a 3-hour refactor at 2 AM sends you a message with the diff summary. You read it at 6 AM and decide what's next.
  • Two-way by default. Every chat is a reply thread. You can type "stop the refactor, ship the login fix first" and the agent running receives it as its next prompt. No laptop needed.
  • Multiplexed channels. One Telegram account can hold dozens of chats. Each chat maps to one amux worker, giving every agent its own private channel while keeping your phone's notification stream organized by group.

The amux mobile PWA and iOS app offer a richer dashboard view. Telegram is complementary: use it for notifications and quick steering, use the dashboard for fleet-wide oversight.

How the Telegram connector works

amux uses Telegram's long-polling API. The server makes outbound HTTP requests to api.telegram.org every 45 seconds to retrieve new messages. No inbound port is needed, and the connector works from behind NAT, a VPN, or a local network without any router configuration.

Outbound messages from agents go through POST /api/telegram/send on the amux server. The auto-relay feature takes this further: it captures terminal output from every running worker and forwards it to the linked Telegram chat automatically, without agents needing to call any API themselves. Formatting is converted from terminal ANSI codes to Telegram-compatible Markdown: code blocks are preserved, color codes are stripped, links render as clickable text.

A deduplication layer prevents the relay from sending the same output block twice if a session reconnects or the polling cycle overlaps a message boundary. Long outputs are split into multiple messages at natural line breaks, staying within Telegram's 4096-character per-message limit.

Setup: five steps to your first agent notification

Step 1 — Create a Telegram bot

Open Telegram and start a chat with @BotFather. Send /newbot, choose a display name (e.g. "My amux Fleet"), then choose a username ending in bot (e.g. myfleet_amux_bot). BotFather returns a token:

Done! Use this token to access the HTTP API:
123456789:AAF_YourTokenHere-xyz

Copy the token. You'll need it in the next step.

Step 2 — Add the token to server.env

# ~/.amux/server.env
TELEGRAM_BOT_TOKEN=123456789:AAF_YourTokenHere-xyz

Restart amux to pick up the new variable:

# macOS
launchctl kickstart -k gui/$(id -u)/com.amux.server-rs

# Linux (systemd)
systemctl --user restart amux.service

Step 3 — Link your Telegram chat

Find the bot you just created in Telegram and open a chat with it. Send /start. amux picks up this message on its next poll cycle (within 45 seconds) and registers your chat ID. The bot replies with a confirmation. Your personal chat is now linked.

For team setups, you can add the bot to a Telegram group instead. Everyone in the group can read agent output and send steering messages. Permissions are controlled at the amux level, not the Telegram level.

Step 4 — Test the connection

Send a message from any running amux session:

curl -sk -X POST \
  -H 'Content-Type: application/json' \
  -d '{"text":"hello from amux"}' \
  $AMUX_URL/api/telegram/send

The message appears in your Telegram chat within a second. If it doesn't arrive, check ~/.amux/logs/server-rs.log for a line containing telegram — missing token and invalid chat ID are the two common failure modes, both reported in the log with a specific error code from Telegram's API.

Step 5 — Route messages to specific workers

By default, all linked chats receive fleet-wide broadcast messages. To steer a specific worker, link a chat to that worker with /link:

/link @worker-name

After linking, messages you type in that chat are forwarded to the named worker's session as new prompts. Agent output from that worker also flows back to that chat. This creates a private channel per worker — useful for a fleet where different people own different agents.

Routing with @lane mentions

In a shared Telegram group where multiple workers are linked, you can address a specific worker by name:

@backend-agent fix the auth middleware first, then resume the refactor

amux parses the @mention, matches it to the registered worker name, and routes the message to that session only. Other workers in the same group do not receive it. This gives a team a single Telegram group with clean per-worker routing without creating one chat per agent.

Unknown @mentions (a name that doesn't match any registered worker) are surfaced as a warning in the bot's reply rather than silently dropped. This prevents misdirected messages from going nowhere without feedback.

Overnight monitoring patterns

amux is built for unattended overnight runs. The self-healing layer handles the common failure modes: context exhaustion triggers auto-compact, a crashed session restarts and replays the last message, and the watchdog keeps every worker in the fleet alive without intervention. Telegram adds the visibility layer on top.

A useful overnight pattern:

  1. Start your fleet before bed. Each agent gets its task via the board.
  2. Configure the auto-relay to send a summary message when a card moves to done.
  3. Sleep. Your phone receives pings as agents complete tasks through the night.
  4. In the morning, read the overnight summary in Telegram. Reply with the next priority for any agent that completed early and is waiting for input.
  5. Agents pick up the new task without you opening a browser.

This pattern keeps the fleet productive across time zones, overnight windows, and weekends without requiring anyone to sit in front of a screen.

Sending from inside a session

Agents can send Telegram messages directly using the amux REST API. This is useful for milestone notifications, error alerts, or structured summaries:

# From inside a Claude Code session (AMUX_URL is in the environment)
curl -sk -X POST \
  -H 'Content-Type: application/json' \
  -d '{
    "text": "Feature branch shipped. PR: https://github.com/org/repo/pull/42\nTests: 147 passed, 0 failed.",
    "parse_mode": "HTML"
  }' \
  $AMUX_URL/api/telegram/send

HTML parse mode lets agents send formatted messages with bold, italic, and clickable links. The endpoint accepts parse_mode: "HTML" or parse_mode: "Markdown". Omit parse_mode for plain text.

To send to a specific worker's linked chat rather than the fleet broadcast:

curl -sk -X POST \
  -H 'Content-Type: application/json' \
  -d '{"text":"task complete","worker":"backend-agent"}' \
  $AMUX_URL/api/telegram/send

Frequently asked questions

How do I get Telegram notifications from AI coding agents?

Install amux, create a Telegram bot via @BotFather, add TELEGRAM_BOT_TOKEN=... to ~/.amux/server.env, restart amux, then send /start to your bot in Telegram. The auto-relay forwards agent terminal output to your chat from that point on. Total setup time: under five minutes.

Can I send messages to a running AI coding agent via Telegram?

Yes. Link a chat to a specific worker with /link @worker-name in your Telegram chat. After linking, messages you type in that chat are forwarded to the worker's session as new prompts. The agent reads the message and responds — no laptop required.

Does the Telegram connector need an open inbound port?

No. amux uses Telegram's long-polling API, which means the server makes outbound requests to Telegram's servers. Your machine never receives an inbound connection from Telegram. The connector works from behind NAT, a firewall, or a fully local network with no router configuration.

Can I route Telegram messages to different AI agents?

Yes. Use /link @worker-name in a Telegram chat to bind that chat to a specific worker. You can create separate Telegram group chats and link each to a different agent, or use @lane mentions in a shared group to route specific messages to specific workers without creating multiple chats.

What formatting does the Telegram relay support?

The relay converts terminal output to Telegram Markdown: fenced code blocks are preserved, ANSI color codes are stripped to plain text, links render as clickable, blockquotes and strikethrough pass through unchanged. Long outputs are split into multiple messages at line breaks to stay within Telegram's 4096-character limit.

How is this different from just checking the amux dashboard?

The dashboard is a browser tab you actively open and check. Telegram pushes notifications to your phone with sound and lock-screen previews the moment an agent completes a task or hits an issue. You also reply directly from Telegram to steer the next task. The dashboard is better for fleet-wide oversight and visual monitoring; Telegram is better for staying informed passively and steering without interrupting your day.
