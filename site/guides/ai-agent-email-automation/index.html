AI Agent Email Automation — Send, Reply, and Attach Files from Claude Code (2026)

AI agents can send and reply to email from your domain, with file attachments, via amux's Gmail API integration. No AppleScript, no SMTP config, no browser required. Real threading, your signature, multiple accounts. Updated August 2026.

Quick answer: Authorize a Gmail account in amux once (GET /api/gmail/auth?account=you@yourdomain.com), then any agent can POST /api/email/send or /api/email/reply to send email from your real account — with your domain, your signature, and optionally file attachments. The full email API is a JSON interface over the Gmail API: no Mail.app, no SMTP credentials, no brittle AppleScript.

Why AI Agents Need a Proper Email API

The two common approaches to agent email automation both have critical failure modes:

  • AppleScript / Mail.app — requires Mail.app running as a desktop process, uses fragile UI scripting, and the most common "reply" pattern (set content) silently sends a blank email. The message looks sent from the sending side; the recipient gets nothing. This is a documented failure that cost a real production incident.
  • Raw SMTP — works for send, but doesn't give agents threading context (message IDs, In-Reply-To, References), requires managing credentials and TLS separately, and produces emails that bypass Gmail's sent-mail threading.

amux's approach: a JSON API over the Gmail API. Agents call /api/email/send and /api/email/reply with a plain JSON body. The server handles OAuth tokens, MIME formatting, threading headers, and signature injection. Agents never touch credentials or MIME directly.

How to Set Up AI Agent Email Automation

Step 1: Connect a Gmail account

# Get the OAuth URL (run this in a browser or open the URL it returns)
curl -sk "$AMUX_URL/api/gmail/auth?account=you@yourdomain.com"

# List connected accounts
curl -sk "$AMUX_URL/api/gmail/accounts"

Open the returned URL in your browser, approve Gmail access, and amux stores the token in ~/.amux/gmail-tokens/. The account is now available for agents.

Step 2: Send a new email from an agent

curl -sk -X POST -H 'Content-Type: application/json' \
  -d '{
    "to": "investor@example.com",
    "subject": "Weekly product update — Aug 19",
    "body": "Here is this week'\''s update.\n\nFeatured shipped:\n- Email with attachments\n- BM25 board search\n- Connectors tab\n\nMetrics attached.",
    "from": "ceo@yourstartup.com"
  }' \
  $AMUX_URL/api/email/send

The response includes a message_id you can use to read the sent message back or thread future replies.

Step 3: Reply in a thread

# Search for the thread first
curl -sk "$AMUX_URL/api/email/search?q=investor+update&days=7&limit=5"

# Reply using the message_id from the search result
curl -sk -X POST -H 'Content-Type: application/json' \
  -d '{
    "message_id": "<the-message-id@mail.gmail.com>",
    "body": "Following up on the metrics I sent — happy to jump on a call.",
    "from": "ceo@yourstartup.com"
  }' \
  $AMUX_URL/api/email/reply

amux sets In-Reply-To and References headers automatically. The reply threads correctly in Gmail for both sender and recipient.

Step 4: Attach a file (August 2026)

curl -sk -X POST -H 'Content-Type: application/json' \
  -d '{
    "to": "board@yourstartup.com",
    "subject": "Q3 metrics",
    "body": "Board metrics for Q3 attached.",
    "from": "ceo@yourstartup.com",
    "attachments": [
      {
        "filename": "q3-metrics.pdf",
        "content": "<base64-encoded-PDF-bytes>",
        "mime_type": "application/pdf"
      }
    ]
  }' \
  $AMUX_URL/api/email/send

Attachments are sent as multipart/mixed. The file appears as a standard email attachment in Gmail. You can attach multiple files in one request by adding more objects to the array.

Common Email Automation Workflows

Weekly investor update with metrics attachment

An agent runs every Monday morning via the amux scheduler. It pulls metrics from your database or API, generates a PDF or CSV summary, and sends the report to your investor list — from your real email address, with the report as an attachment. Setup:

curl -sk -X POST -H 'Content-Type: application/json' \
  -H "X-Amux-Session: $AMUX_SESSION" \
  -d '{
    "title": "Weekly investor email with metrics",
    "session": "your-session-name",
    "command": "pull this week'\''s metrics from /api/metrics, generate a summary, and email it to the investor list with the CSV attached",
    "schedule_expr": "weekly on Monday at 8am"
  }' \
  $AMUX_URL/api/schedules

Customer follow-up triggered from the board

When a board card moves to "Done", an agent checks the card's linked CRM contact and sends a follow-up email. The agent reads the card context, drafts a relevant message, and sends it from the appropriate account.

Inbound email triage

An agent reads the inbox every morning, categorizes messages by topic (sales inquiry, support request, investor, partnership), adds contacts to the CRM, and drafts reply suggestions on the board as cards for review. The agent sends nothing until a human moves the draft card to "Approved".

# Read inbox
curl -sk "$AMUX_URL/api/email/inbox?count=20&days=1"

# Read a specific message
curl -sk "$AMUX_URL/api/email/message/<message_id>"

Onboarding sequence

When a new CRM contact is added, an agent sends a sequence of 3 onboarding emails spaced 2 days apart. Each email is personalized using the contact's name, company, and role from the CRM record. The agent uses /api/email/send for the first message and /api/email/reply for the follow-ups so they thread correctly.

Email API Reference

Endpoint Method Purpose
/api/email/send POST Send a new email (not a reply). Pass to, subject, body, from, optional cc, attachments.
/api/email/reply POST Reply in a thread. Pass message_id, body, from, optional reply_all, attachments.
/api/email/inbox GET Read inbox, newest first. Query params: account, count, days.
/api/email/search GET Search email. Required: q. Optional: account, limit, days, mailbox.
/api/email/message/<id> GET Read a single message by RFC822 message ID. Returns full body, headers, and attachment metadata.
/api/email/log GET Audit log of sent emails. Query params: session, days, limit.
/api/gmail/accounts GET List connected Gmail accounts available for sending.

Frequently Asked Questions

Can AI agents send email from my domain?

Yes. amux connects to Gmail or Google Workspace via the Gmail API using OAuth. When an agent sends email, it goes from your real account — your domain, your display name, your Gmail signature appended automatically. Recipients see it as sent from you, not from a third-party service.

Can AI agents send emails with file attachments?

Yes, as of August 2026. Both /api/email/send and /api/email/reply accept an attachments array. Each entry has filename, content (base64), and mime_type. The email is sent as multipart/mixed. Attached files are also retrievable via the amux attachment download endpoint for later reference or audit.

How is this different from AppleScript or raw SMTP?

AppleScript requires Mail.app and the most common reply pattern silently sends blank emails. Raw SMTP works for outbound but lacks threading context. amux's Gmail API integration handles OAuth, threading headers, signatures, and attachments in a single JSON API call. No desktop process required, no credential management, no MIME formatting in agent code.

Can one amux installation send from multiple email accounts?

Yes. Authorize each account with GET /api/gmail/auth?account=<email> and pass the desired from address when sending. You can route customer-facing email from one address and internal ops from another, all from the same amux instance.

What email workflows work well with AI agents?

Reliable use cases: weekly digest emails built from structured data, customer follow-ups triggered by board events, onboarding sequences, investor updates with attached reports, and reply drafts that pull context from the CRM or database. Tasks requiring nuanced tone judgment work better as draft-and-approve workflows: the agent drafts, a human reviews, the agent sends on approval.
