Live Status and Restarts

amux reads every session's terminal to show Working, Needs Input or Idle, and keeps agents going through usage limits and restarts.

Silent clip, recorded from a real amux server with real agents, on a laptop and an iPhone-sized screen. Agent work is sped up. GIF version for docs and READMEs.

How it works

  1. amux parses ANSI-stripped tmux output to detect: Working / Needs Input / Idle
  2. Usage limits: amux holds message delivery and resumes the agent at the provider's reset time
  3. Reboots: the OS service restarts the amux server, and on macOS a login job brings every non-archived worker back in its own conversation
  4. Context: Claude Code compacts its own context; amux lets you set the compaction threshold
  5. YOLO mode: --yolo skips Claude Code's tool-approval prompts, so unattended workers never wait on one
  6. Stalls: stalled board work and stuck orchestrators are surfaced, and owner alerts fire

Restarting a crashed agent process is not built into the amux server today. On macOS, an optional script, scripts/tmux-watchdog.sh, restarts crashed Claude Code workers; it runs as a separate launchd job that the installer does not set up. Nothing does this on Linux or for other providers.

When to use this

  • Running agents overnight while you sleep
  • Agents that keep hitting provider usage limits
  • Agents getting stuck on tool-approval prompts in batch work

Try amux

Run an AI engineering team of Claude Code, Codex and Gemini CLI agents from one dashboard or your phone. One Rust binary. Free to self-host.

amux register myproject --dir ~/Dev/myproject --yolo
amux serve  # → https://localhost:8824
