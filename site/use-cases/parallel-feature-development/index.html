Parallel Feature Development with AI Agents

A full sprint's features — shipped in a day.

Run one AI coding agent per feature branch simultaneously. amux coordinates each session on a shared kanban board, prevents git conflicts, and lets you monitor every agent from a single dashboard or your phone. A four-person sprint's worth of features — auth, search, payments, onboarding — runs in parallel and finishes together instead of one after another.

amux works with Claude Code, Codex CLI, and Gemini CLI in the same fleet. Each agent claims tasks atomically — no two agents pick the same feature card. If one crashes overnight, the self-healing watchdog restarts it and replays the last message so work continues unattended.

How to run parallel feature development

Step 1: Register one session per feature

Each feature gets its own named amux session. All can share the same repo directory — amux isolates them on separate branches.

amux register auth     --dir ~/Dev/app --yolo
amux register search   --dir ~/Dev/app --yolo
amux register payments --dir ~/Dev/app --yolo
amux register onboard  --dir ~/Dev/app --yolo

Step 2: Post tasks to the shared board

Add a card per feature. The board is the coordination layer — agents claim tasks atomically so no two agents start the same work.

# From the dashboard, CLI, or phone — add one card per feature:
amux board add "Build auth: JWT login + refresh tokens"
amux board add "Build search: full-text across notes and tasks"
amux board add "Build payments: Stripe checkout flow"
amux board add "Build onboarding: multi-step wizard"

If auth must land before payments can start, set a dependency:

# Mark payments as blocked until auth is done
curl -sk -X PATCH -d '{"blocked_on":"CARD-AUTH-ID"}' $AMUX_URL/api/board/CARD-PAYMENTS-ID

The GET /api/board/ready endpoint returns only unblocked tasks, so agents pull work in the correct order automatically.

Step 3: Start all agents at once

amux start-all

All registered sessions launch simultaneously. amux staggers startup by one second per agent to avoid a cold-boot memory spike. Each agent reads from the board, claims a task, creates a branch, and starts coding.

Step 4: Monitor from the dashboard or your iPhone

Open https://localhost:8824 or the iOS app. Each agent's status, current card, branch, and most recent output appear in real time. If an agent goes quiet for too long, the self-healing watchdog flags it in the dashboard — and restarts it if it has crashed.

You can approve pull requests, send new instructions to a specific agent, or reassign a card — all from your phone, without touching a laptop.

Step 5: Handle blocked agents

When one feature depends on another, mark it blocked:

amux board doing CARD-AUTH-ID     # auth is in progress
# payments agent sees no ready task and waits

The dashboard shows a blocked dimension across the fleet. When auth completes and its card moves to done, payments automatically becomes ready and any idle agent can claim it.

Avoiding git conflicts in a parallel run

The standard approach is one branch per agent:

  • Each session works on feature/auth, feature/search, etc. — never on the same branch simultaneously.
  • amux's shared-checkout guard refuses git add -A inside a shared working directory, which is the most common accidental cross-branch write.
  • If two sessions do end up on the same branch, amux warns you before either commits.

Agents that need shared infrastructure (a new DB table, a shared utility module) should be sequenced: one agent writes the shared piece first, the rest depend on that card completing before they begin.

Runtime flexibility: mix Claude Code, Codex, and Gemini CLI

amux is not tied to a single AI runtime. Register each session with whatever CLI fits the task:

# Claude Code for complex reasoning tasks
amux register auth --model claude-sonnet-5 --dir ~/Dev/app

# Codex CLI for fast, high-volume tasks
amux register search --model gpt-5 --dir ~/Dev/app

# Gemini CLI for tasks that need large context windows
amux register onboard --model gemini-2-5-pro --dir ~/Dev/app

The dashboard, board, and phone app treat all runtimes identically. See the Claude Code vs Codex vs Gemini CLI guide for a per-runtime feature comparison.

Running the fleet overnight

Set agents loose before you sleep. amux keeps them running unattended:

  • Context compaction fires automatically before any session hits its context limit — no stalled agents at 3am.
  • Crashed sessions restart themselves and replay the last prompt.
  • The board prevents any agent from picking up a task that was already completed by another.

Wake up to a queue of pull requests, one per feature, ready to review. See AI coding while you sleep for the full overnight workflow.

What amux is

amux is an open-source control plane for running an AI engineering team from a single dashboard or your phone. It launches, monitors, and self-heals dozens of parallel Claude Code, Codex, or Gemini CLI sessions, with built-in kanban, notes, CRM, email, browser automation, and a scheduler. Self-healing, single Rust binary, zero external dependencies, MIT licensed.

Run your first parallel sprint

Install amux, register your feature sessions, and start them all at once. Open source, self-hosted, zero vendor lock-in.

curl -fsSL https://amux.io/install.sh | bash
amux register feature-1 --dir ~/Dev/myapp --yolo
amux register feature-2 --dir ~/Dev/myapp --yolo
amux start-all
# → open https://localhost:8824
