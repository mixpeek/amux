Test Webhooks Locally with a Stable Public URL

Receive real webhook events on your local machine without reconfiguring your webhook provider on every restart. Updated August 2026.

To test webhooks locally, you need a public HTTPS URL that routes to your machine. amux tunnel exposes any local port at a stable URL — https://<id>.t.amux.io — that survives machine restarts, network changes, and IP reassignments. Your machine dials out to the amux cloud gateway; the gateway forwards incoming webhook payloads to your local server. No inbound port, no firewall rule, no static IP. Register the URL with Stripe, GitHub, Twilio, or any webhook provider once and leave it there through your entire development cycle.

amux tunnel start 3000
# → Tunnel live: https://a3f9bc12.t.amux.io
# Forwarding to http://localhost:3000

Why Stable URL Matters for Webhooks

The fundamental problem with tools that give you an ephemeral public URL is that you have to re-register it with your webhook provider every time it changes. With ngrok's free tier, the URL changes on every restart. That means:

  • Every time you restart your machine, you open the Stripe dashboard (or GitHub, or Twilio) and paste a new URL.
  • If you forget, webhook deliveries go to the old URL and silently fail.
  • You cannot share a webhook URL with teammates who need to fire test events at your local server.

amux tunnel generates the URL from a hash of your account token. Same token, same URL, always. You configure the webhook provider once and stop thinking about it.

How to Set Up Webhook Testing with amux

Step 1 — Install amux and start the server

If amux is not installed:

curl -fsSL https://amux.io/install.sh | bash
amux serve       # dashboard at https://localhost:8824

The tunnel client is built into the same binary — nothing extra to install.

Step 2 — Start the tunnel on your webhook port

amux tunnel start 3000   # replace 3000 with your app's port

amux connects outbound to the cloud gateway and prints your stable public URL:

Tunnel live: https://a3f9bc12.t.amux.io
Forwarding → http://localhost:3000

Note your URL. It will be the same on every restart.

Step 3 — Register the URL with your webhook provider

Go to your webhook provider's dashboard and paste the https://....t.amux.io URL as the endpoint. Examples:

  • Stripe: Developers → Webhooks → Add endpoint → paste URL, select events.
  • GitHub: Repo Settings → Webhooks → Add webhook → paste URL, select content type application/json.
  • Twilio: Phone number configuration → Webhook URL for SMS/voice.
  • Shopify: Settings → Notifications → Create webhook → paste URL, choose format.

You do this once. The URL does not change between sessions.

Step 4 — Trigger an event and verify delivery

Use your provider's "Send test webhook" or "Redeliver" feature to fire an event. Check your local server logs to confirm the payload arrived. Then make changes to your handler code and fire another test — the same URL stays live as long as amux is running.

# Example: inspect the raw payload in your local Express app
app.post('/webhooks/stripe', express.raw({type:'application/json'}), (req, res) => {
  console.log('Received:', JSON.stringify(JSON.parse(req.body), null, 2));
  res.sendStatus(200);
});

When to Use amux Tunnel vs ngrok for Webhooks

Use amux tunnel when:

  • You already run amux for AI agent orchestration — the stable URL costs you nothing extra.
  • You are tired of re-pasting URLs into Stripe/GitHub/Twilio every morning.
  • You want to share a stable webhook endpoint URL with teammates working on the same integration.
  • You want to subscribe a real service (like Google Calendar via iCal feed) and need the URL to survive restarts.

Use ngrok when:

  • You need the request inspection UI (ngrok's localhost:4040 inspector is genuinely excellent — replay, headers, body diff).
  • You need WebSocket or SSE passthrough.
  • You need a custom domain or TCP tunneling.
  • You do not run amux and want the fastest possible setup for a one-off test.

Frequently Asked Questions

Do I need a static IP to test webhooks locally?

No. amux tunnel works outbound: your machine connects to the cloud gateway, and the gateway forwards webhook POSTs to your machine over that connection. Your IP address is irrelevant. You do not need to configure NAT, open any inbound port, or ask your ISP for a static IP.

What is the difference between amux tunnel and ngrok for webhook testing?

The practical difference is URL stability. ngrok free tier gives you an ephemeral URL that changes on every restart. amux tunnel gives you a stable URL derived from your account token — same URL across every restart. ngrok wins on the request inspection UI (excellent), WebSocket support, TCP tunneling, and custom domains. amux tunnel wins when you want a stable development URL without paying for ngrok Pro, and when you are already using amux for agent orchestration.

Does the webhook URL change when I restart my machine?

No. The URL is derived from a hash of your amux cloud token. Same token, same URL, always. The format is https://<hash>.t.amux.io. You register it once with your webhook provider and it stays valid through restarts, network changes, and IP reassignments.

Is the tunnel URL public — can anyone reach it?

Yes. The URL is publicly reachable. It is not behind any authentication. The hash-derived URL is not guessable from a sequential ID, but you should still validate webhook signatures on your local server exactly as you would in production. Treat every incoming payload as untrusted and verify the provider's HMAC signature before acting on it.

Does amux tunnel support WebSockets or Server-Sent Events?

No. amux tunnel buffers responses and does not pass streaming protocols through. For standard webhook deliveries — where the provider sends an HTTP POST and expects a 200 OK — it works correctly. For WebSocket or SSE workloads, use ngrok or Cloudflare Tunnel.

Is amux tunnel free?

The tunnel feature requires an active amux cloud subscription. The core amux platform — agent orchestration, dashboard, kanban board, scheduler, CRM, email, notes — is open source, MIT licensed, and runs entirely on your machine at no cost.
