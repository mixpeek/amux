amux for Python Developers Updated Sep 2026

Python's ecosystem is vast: monorepos, dozens of test modules, long migration chains, ML pipelines. amux lets you work all of them simultaneously — one Claude Code agent per package, per test file, per migration. Monitor them all from your browser or phone.

Why Python + amux Works

Python projects sprawl naturally: multiple packages in a monorepo, test suites measured in thousands of files, migration chains that take days to untangle. The answer to scale is parallelism — and amux brings that to the agent level. Instead of one Claude Code agent doing one thing, you run ten agents doing ten things at once, each aware of what the others are doing via a shared kanban board.

  • One agent per package: Migrating a monorepo from Python 3.9 to 3.12? Assign one agent per package. They run simultaneously — work that would take days finishes in hours.
  • One agent per test module: Run 10 agents writing unit tests across 10 test files. Cover an entire module in a single afternoon.
  • Dependency upgrade agents: When a major dependency (Django, SQLAlchemy, Pydantic v2) releases a breaking version, use agents to handle the migration per-module, coordinated via the board.
  • Type annotation blitzes: Adding mypy or pyright to a large untyped codebase? One agent per file or module, all running in parallel.

Python-Specific Workflows

# Install amux (single Rust binary)
curl -fsSL https://amux.io/install.sh | bash

# Register separate agents for different parts of your Python project
amux register auth-agent --dir ~/myproject --yolo
amux register api-agent  --dir ~/myproject --yolo
amux register tests-agent --dir ~/myproject --yolo

# Start them all
amux start auth-agent api-agent tests-agent

# Assign tasks via the board
amux board add "Migrate auth/ to Pydantic v2" --session auth-agent
amux board add "Write pytest fixtures for api/" --session api-agent
amux board add "Type-annotate tests/ with pyright" --session tests-agent

# Monitor from the web dashboard or iOS app
amux serve  # → https://localhost:8824

CLAUDE.md for Python Projects

Every Claude Code agent reads a CLAUDE.md file from your project root. For Python projects, this is where you declare your conventions once so every agent follows them. See the CLAUDE.md templates guide for full examples.

# CLAUDE.md (place at your project root)
# Python conventions
- Always activate the venv at `.venv/` before running commands
- Use `uv` for dependency management (not pip)
- Run `pytest -x --tb=short` to confirm a fix before marking a task done
- Type hints required on all new functions (pyright strict)
- Import style: absolute imports only, no relative imports across packages

# Agent coordination
- Check the board before starting any task: `amux board ls`
- Mark your task `doing` before touching files
- Mark `done` only after tests pass

Agents in different tmux panes share the same CLAUDE.md, so you get consistent conventions across the whole fleet without repeating yourself.

Auto-Drain: Agents That Pick Up Their Own Tasks

Once you have agents running, you can load the board with tasks and let agents claim them automatically. Enable auto-drain per session:

# Each agent claims the next todo card when idle
amux board drain on auth-agent
amux board drain on api-agent
amux board drain on tests-agent

Now you can add 50 migration tasks to the board and walk away. Agents claim cards atomically — no two agents touch the same task. See the running 10+ agents guide for the full pattern.

Data Science and ML

Python is the lingua franca of ML. amux handles the parallelism that makes ML work faster:

  • Generate model training scripts across multiple architectures simultaneously
  • Write data validation and cleaning pipelines for each data source in parallel
  • Implement paper reproductions with one agent per paper
  • Generate experiment notebooks and evaluation harnesses across a model grid

Async by Nature

Python developers already think in async terms: asyncio, Celery, multiprocessing. amux applies the same pattern at the agent level. Fire off tasks, check back when they're done, aggregate results from the board. The mental model is familiar — the execution is new.

FAQ

How do I use Claude Code with a Python monorepo?

Register each package as a separate amux session pointing to your monorepo root. Agents share the same directory so they can read each other's changes. Assign one agent per package via the shared kanban board. Use CLAUDE.md files in each package directory to give agents package-specific context on top of the root-level conventions.

Can I run pytest across multiple agents with amux?

Yes. Launch one Claude Code agent per test module or test file. Each agent runs its own pytest loop, fixing failures it encounters. amux shows all agents on a shared dashboard so you can see which tests are passing across the whole fleet at once.

How does amux help with Python dependency upgrades?

When a major dependency like Django, SQLAlchemy, or Pydantic releases a breaking version, spawn one agent per affected module via amux. Add a board card for each migration task, let agents claim them atomically, and monitor progress from the web dashboard or iOS app. No two agents will claim the same card.

Does amux work with Python virtual environments?

Yes. Set the venv path in your CLAUDE.md so every agent activates the same environment. amux doesn't manage Python environments — it orchestrates Claude Code agents that run inside whatever environment you configure. A typical CLAUDE.md line: Always activate .venv/ before running any command.

How do I install amux for Python development?

curl -fsSL https://amux.io/install.sh | bash. No Python required — amux is a single Rust binary. Register your project directory, start agents, and open the dashboard at https://localhost:8824.
