amux › Your data

You own your data and your workflows

Last updated: November 10, 2026

Short answer: everything amux keeps lives on a machine you control, in plain formats: a SQLite database, markdown, and your own folders and git repositories. One command exports all of it to a single file, and the same file imports into any other amux server. You can leave whenever you want and take everything with you.

Where your data lives

Board, schedules, messages~/.amux/amux.db

One SQLite file. Cards and their history, schedules, calendar events, messages, contacts, skills and memories.

Settings~/.amux/server.env

Plain text. Your keys and options stay here and never leave the machine.

Your workyour folders and git repos

Agents write code and documents into your own folders. amux never moves them anywhere else.

Workflowsschedules, skills, prompts

Stored as rows and markdown you can read, copy and edit. Nothing is locked in a format only we can open.

Export everything in one command

  1. Write the export file. On the machine running amux: 
    amux export
    It writes amux-<host>-<date>.amuxmove.json and prints what it holds, for example: 
    exported 47133 rows (schema 156, commit 1cdc2039a)
  cal_events           458
  crm_contacts         327
  issues               33821
  schedules            1251
  skills               14
  ...
    The file is one readable JSON document: your board cards with their history, schedules, calendar, messages, contacts, skills, memories, and your worker and board setup. It never contains passwords, API keys or tokens.
  2. Keep it, read it, or move it. Open it in any editor, load it into a script, or bring it into another amux server: 
    amux import amux-myhost-20261110.amuxmove.json --to https://<you>.amux.io --user you@example.com
    Import always shows a dry run first, only adds rows, and never overwrites or deletes anything already there.

Or pull one thing at a time

Every part of amux is also a plain web API on your own server. Run these on the machine running amux:

U=$(amux url)
curl -sk "$U/api/board/export?format=md"   -o board.md        # every card, readable
curl -sk "$U/api/board/export?format=json" -o board.json
curl -sk "$U/api/schedules"                -o schedules.json
curl -sk "$U/api/calendar.ics"             -o calendar.ics    # opens in any calendar app
curl -sk "$U/api/crm/contacts"             -o contacts.json
curl -sk "$U/api/memories"                 -o memories.json

Or copy the raw files

For a byte-for-byte backup, including your settings and keys, copy the folder. Keep this copy somewhere private, because it holds your secrets:

sqlite3 ~/.amux/amux.db ".backup $HOME/amux-backup.db"   # safe while amux is running
tar -czf ~/amux-folder.tar.gz -C ~ .amux

Where you run amux

SetupWhere the data isHow to take it with you
Self-hostedYour computer, in ~/.amux and your folders.Any of the methods above. It is already on your disk.
amux CloudYour own dedicated server at yourname.amux.io, shared with no one (details).Open the Terminal tab on your server, run amux export, then download the file from the Files tab. To move to your own computer, install amux and run amux import there.
ConciergeWe set amux up on a computer you own (how it works).Same as self-hosted. The workflows we build run on your machine and stay there if you stop working with us.

Leaving

  • Self-hosted: stop amux and your data stays exactly where it is. There is no account to close.
  • amux Cloud: export first, then cancel. Canceling keeps a final snapshot for 30 days in case you come back. Deleting your account erases the server and its backups right away (details).
  • The code is public. amux is source-available under MIT + Commons Clause on GitHub, so you can keep running the version you have and check every claim on this page.

Questions

Do I need to ask you for an export?

No. amux export runs on your own server whenever you want, with no request and no waiting.

Can I open the export without amux?

Yes. It is JSON, the board export is also available as markdown, and the calendar is a standard .ics file.

Does the export include my API keys?

No. amux export leaves out every password, key and token on purpose. Only the raw folder copy includes them.

How do I export from amux Cloud?

Open the Terminal tab on your server, run amux export, then download the file from the Files tab. amux import loads it into any other amux server.

What about the code and documents agents wrote?

Those are already in your own folders and git repositories. amux works in them; it does not keep a separate copy.
