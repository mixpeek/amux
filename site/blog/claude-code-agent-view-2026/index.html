Claude Code Agent View: What It Shows and What It Misses at Scale

Claude Code now includes a built-in Agent View for watching sub-agents. Understanding its scope is the first step to knowing whether you need anything else.

What is Claude Code Agent View?

Claude Code Agent View is a pane inside the Claude Code terminal interface that shows activity from sub-agents spawned by the current session. When Claude Code uses its Task tool to spin up parallel sub-agents within a single conversation, Agent View surfaces what each one is working on, what tools it is calling, and whether it has finished.

Anthropic shipped it to reduce the black-box feel of agentic work. Before Agent View, a Claude Code session running multiple internal sub-agents looked like a single cursor with no visibility into what was happening underneath. Now the pane shows a tree of active tasks with live status.

What Agent View Shows

  • Sub-agent tree: Every sub-agent that the parent session spawned via Task tool, organized hierarchically.
  • Tool calls: Which tools (Bash, Edit, Read, WebSearch) each sub-agent is running at the moment.
  • Status: Running, waiting, completed, or failed for each sub-agent.
  • Output snippets: Recent text output from each sub-agent, inline in the tree.

For tasks where one Claude Code session orchestrates several parallel workstreams internally, Agent View gives real-time feedback that was missing before. A code review that spawns three sub-agents to review different modules, for example, now shows all three in a single glanceable pane.

The Boundary: One Session

Agent View's scope is a single Claude Code session. That is the hard boundary.

It shows sub-agents spawned by the current conversation's Task tool. It does not show:

  • Other Claude Code sessions running in separate terminals or tmux panes
  • Claude Code sessions started by other team members or on other machines
  • Codex CLI or Gemini CLI (agy) processes running alongside Claude Code
  • Sessions that crashed and were restarted
  • Historical output from sessions that have already completed

This is not a gap in Anthropic's design. Agent View is a session-scoped tool. It answers "what is this conversation's sub-agent fleet doing right now?" The question "what are all of my coding agents doing across my machine?" is a different question and requires a different layer.

Scaling Beyond One Session

The typical team starts with one Claude Code session and discovers Agent View. That works well up to 3-5 sub-agents within a single conversation, on tasks that fit inside one context window.

Past that, the pattern shifts. You want independent Claude Code processes: separate terminal sessions, each working on their own task, each with their own context window, able to run overnight without one session's crash bringing down the whole fleet. Sub-agents inside one conversation share the parent's context window and lifecycle. Independent sessions do not.

Running 10+ independent Claude Code sessions introduces new coordination problems:

  • Visibility: You have 10 tmux panes and no way to see all of them at once on a phone.
  • Task distribution: Without a shared board, agents duplicate work or sit idle.
  • Crash recovery: If a session dies at 2 a.m., nobody restarts it until morning.
  • Escalation: An agent that gets stuck waiting for input has no way to alert you.
  • Review: Scrollback across 10 windows takes significant time and misses context.

These are control-plane problems. Agent View does not address them because they sit outside its scope.

Agent View vs. External Control Plane

Shows sub-agents inside one session Yes Yes (each session's output is peekable)
Shows independent sessions across your machine No Yes

Overnight unattended operation Limited (one session's sub-agents) Yes (fleet-level)

Open source N/A (part of Claude Code) Yes (MIT)

They operate at different layers. Agent View is session-scoped introspection. A control plane like amux is fleet-scoped coordination. For most developers running 5 or fewer sub-agents on one task, Agent View is sufficient. For teams running parallel independent sessions continuously, you need the fleet layer.

The two are also compatible. You can run Claude Code under amux supervision. From the amux dashboard you see all your independent Claude Code processes and their status. Inside each Claude Code session, Agent View shows the sub-agents that session has spawned. Nothing conflicts.

Getting Started with amux

# Install
brew install mixpeek/amux/amux

# Register your project and start a fleet
amux register myproject --dir ~/Dev/myproject
amux scale myproject --count 5

# Open the web dashboard
amux serve  # https://localhost:8824

The dashboard opens at port 8824. From there you can see every session's live status, send messages, move kanban cards, and set up the self-healing watchdog for overnight runs. The same interface is available as a mobile PWA.

Frequently Asked Questions

What is Claude Code Agent View?

Claude Code Agent View is a feature inside the Claude Code terminal that shows the sub-agents spawned by the current session. It gives visibility into what each sub-agent is doing within the scope of one Claude Code parent process. It does not show independent Claude Code sessions running in other terminal windows or tmux panes.

Can Claude Code manage multiple independent sessions from one interface?

No. Claude Code Agent View only shows sub-agents spawned by the current session via the Task tool. Independent Claude Code sessions running in separate terminals or tmux panes are not visible to each other. Managing a fleet of independent sessions requires an external control plane like amux.

How do I monitor multiple Claude Code agents at once?

Install amux (brew install mixpeek/amux/amux), then launch your Claude Code workers under amux supervision. The amux web dashboard shows every session's live status, output, and kanban tasks on one screen. You can also use the mobile PWA to check in from your phone.

Does amux replace Claude Code Agent View?

No. They operate at different layers. Claude Code Agent View shows intra-session sub-agents within one Claude Code process. amux shows and coordinates inter-session agents across many independent Claude Code, Codex, or Gemini CLI processes. You can use both simultaneously.

What is the best tool for running 10+ Claude Code agents overnight?

amux is purpose-built for this. It handles crash recovery, stall detection, task distribution via a shared kanban board, mobile monitoring, and owner alerts when something needs attention. See the overnight guide for the full setup.
