## Bottlenecks, ranked by cost

### B1. The builder pinned the server to 5178eb265 for 31 hours (top, fixed)

At 11-04 05:53Z the builder installed e5cc110cb, saw SCHED-706 holding
adoption and logged "waiting up to 1200s", then rolled the build back at
405 s, the second the run ended and before the server's next adoption tick
(`rust-auto-build.log.1:97681-97682`). It then held the commit's build-input
trigger, a851074e6. The binary it restored was built from that same trigger,
and none of the 18 commits since has touched `crates/`, so the hold could
not clear. `/api/pull` said "deploying" the whole time, `/health` reported
5178eb265 while main moved 12 commits on, and the builder logged the hold
every 10 seconds (3,985 lines in today's log, 6,671 in the rotated one).

Cost: no commit since 11-04 05:53Z could be confirmed live, so every
deploy-wake and every "is it live" check for those commits had nothing to
find. The live code did not differ: all 18 commits were scripts, docs and
site.

Fixed in be069d2b7 and a164ef5de (`scripts/rust-auto-build.sh`):
- the wait allows `AMUX_ADOPT_POST_HOLD_GRACE_S` (120 s) after the held
  adoption ends (`verdict=activation_wait_post_hold`);
- a rollback whose restored binary has the same build inputs writes no
  hold and waits out the bounded build backoff instead
  (`verdict=activation_unadopted_same_inputs`);
- a hold already on disk for the installed binary's own inputs is cleared
  with a WARN (`verdict=activation_rollback_hold_same_inputs`), which frees
  this Mac's hold on the builder's first tick on the new script.

Tests: `test-activation-health-wait.sh` 11 passed; `test-build-activation-rollback.sh`
0 failed; each of the three rules mutated out on its own reddens its cells.
