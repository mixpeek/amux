## Proposals

- **18a. A build the server is holding is not rolled back (B1). Done.**
  6b6e13809: the builder keeps waiting past 300 s while a shell schedule run is
  in flight, up to the server's 900 s hold, and logs
  `verdict=activation_wait_shell_hold`. Its test (scripts/test-activation-health-wait.sh,
  in checks.yml) fails on the old cut-off. Landing it also builds a commit
  newer than c71df3ef9, which deploys the board-off change.
- **18b. An answered request keeps the answer (B2).** When a worker closes or
  answers an owner request, store the text of the reply it gave (the final
  assistant message of the turn that consumed the message) on the request, so
  `GET /api/history/MSG-<id>`, `amux requests` and the Messages thread show it.
  "Answered in chat" then points at something you can read without scrolling
  a terminal.
- **18c. WhatsApp sends run where nobody is typing (B3).** Send from a linked
  WhatsApp session in the CUA desktop (`amux computer`), which needs one QR scan
  from your phone, or from the WhatsApp Cloud API connector, whose four
  credentials are unset in server.env. Both remove the dependency on your Mac
  being idle and unlocked. Which one is your call: a linked device sends as you,
  the Cloud API sends as a registered business number (MSG-103132 asked for
  either).
- **18d. A refused sign-in with a valid credential asks the owner (B4).** When
  the door refuses an unlisted address after the right password, post one
  owner alert with the address and a one-tap allow, and tell the user the owner
  has been asked. The owner should not need to find the IP.
