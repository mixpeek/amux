## Bottlenecks, ranked by cost

### B1. One red in the deploy gate held a fix back for 11.5 hours (top)

The builder deploys only commits whose `gate` run passed
(`AMUX_CI_REQUIRED_WORKFLOWS=gate`). `gate` failed on 4b22ba9c4 at 20:56Z,
on `scripts/test-mac-cleanup-lane-tmp.sh` alone (run 43640090658). The
builder logged `ci_gate_held_back` until the next push, 00eb593b1 at 08:22Z.
4b22ba9c4 was amux's change for the Mac CPU constraint, and it was not live
while you were asking whether the server worked.

The same test was the only `gate` red on 8eefef59f (11-12) and 2857482b7
(11-15), every commit this week that changed mac-cleanup-tick.sh. Two
causes, both fixed in 5d4270003:

- The test seeds a repo with `git commit`, and the Ubuntu runner has no git
  identity, so the seed fails and the checkout cases read "removed 0
  entries". The Mac guesses an identity, so it passed locally.
- Its in-use holder slept 30s. A run takes 22s on a quiet Mac and took 53s
  under the pre-push hook, so the holder could end mid-run.

Nobody was told about any of the four `gate` reds this week. Autofix files
a CI card only after two consecutive reds, and the next push always turned
`gate` green first. Card: AF-1234 (file on the first red of a deploy-
required workflow, on the lane that caused it, and tell that lane its
commit is held).

### B2. The pre-push block hid the failing checks

Landing the first version of the fix, the pre-push blocked on the test and
showed its last six lines, all `ok`. The failing checks were earlier in the
output. Finding them took 11 reruns and a read of the hook (about 25
minutes). Card: AF-1235 (show FAIL lines first and name a file with the
