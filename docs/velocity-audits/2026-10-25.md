(a progress line on the worker card), and it still needs your answer.

### B5. Chat tabs report status to a route that refuses them

130 POSTs to `/api/sessions/<worker>@chat/report` returned 404 ("is
amux-helper's Chat tab, not a worker"). They come from
`scripts/hooks/native-status.py` running in a Chat tab. A refused edge is
never deleted, so each later hook fire retries it. Cost: noise and a status
that never arrives.

### B6. Expected refusals drown the error report

395 of the 906 errors are `POST /api/land` 409 `land_queue_off`, from 13
lanes. `amux land` tries the server queue first and then falls back, by
design (`amux:9411`). Each refusal costs about 1 ms. The cost is in the
instrument: the first group a reader sees in `/api/logs/analyze` is an
expected answer.

## Proposals

- **3b (new evidence).** B1 above. This needs your answer: should a worker's
  card carry the progress number its work reports, such as "GS-12 10/56"?
- **10a. A commit that cites no request names the lane's open ones.** Done in
  this run, see below. It does not clean up the 43 already listed. Those
  need amux-admin, or you, to say which commit landed which request.
- **12a. native-status.py does not report for a Chat tab.** The server says a
  Chat tab is not a worker, so the hook should skip `*@chat` and drop its
  spooled edges instead of retrying a 404 forever.
- **13a. `/api/logs/analyze` classes a designed fallback as expected.**
  `land_queue_off` is the answer `amux land` asks for. Give it a verdict
  that keeps it out of the error groups, the same way probes are kept out.
