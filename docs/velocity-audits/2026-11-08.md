## Bottlenecks, ranked by cost

### B1. A dashboard commit still compiles the server (top)

Since 5d0b181ab, a commit that changes no compile input re-stamps the
receipt and goes live without a build. Measured: 69abc30b6 was live 20 s
after its `gate` run started, and 9209e1773 re-stamped too. A commit that
touches `crates/amux-dashboard/static/` still compiles, because rust-embed
bakes the dashboard into the binary: 89c3d6149 (the chip editor, MSG-105291)
compiled and reported `push_to_live_s=430`. Last week 44 commits changed only
the dashboard, the most common kind of change you ask amux for.

Cost: about 2 to 6 minutes per dashboard commit before you can see it, and
MSG-105242 stays unmet for them.

### B2. You asked for faster CI/CD twice, and the first ask is still open

MSG-103534 (amux-admin, `/goal iterate until the full amux cicd is under 1
min`) has been open 143 h. Its sibling MSG-103503 went live as 35d2e7a93.
MSG-105242 (01:34 today) asked me for the same thing. Nothing linked the two
requests, so a second lane started from zero and amux-admin's request reads
open with no owner.

Cost: one repeated request. Duplicated investigation is possible but not
measured.

### B3. Your relay to an isolated worker was refused, and the hint said it would work

MSG-105296 asked `random` to tell `@amux-admin` to keep connectors connected.
The mention annotation that amux appends said
`@amux-admin -> POST $AMUX_URL/api/sessions/amux-admin/send`. The send failed:
"'amux-admin' is an isolated (raw-agent) worker; only its owner can send to
it". You re-routed by hand 4 minutes later (MSG-105297, "Send it to @amux"),
and random relayed it as MSG-105298.

Cost: one extra message from you and a 4-minute delay. The request has not
landed yet.

## Proposals

- **24a (B1).** Serve the dashboard from a snapshot that the builder deploys
  beside the binary (`AMUX_DASHBOARD_DIR`, already honored), and take
  `crates/amux-dashboard/static/` out of the compile inputs the re-stamp
  checks. A dashboard commit then goes live in about 20 s. The embedded
  copy stays as the fallback when the snapshot is missing.
- **24b (B2).** When a new owner request lands with `Amux-Request`, list any
  older open request to another worker with the same ask beside it in
  `amux requests`, so one of the two gets closed with a pointer. Today
  MSG-103534 can be closed as superseded by MSG-105242; that is amux-admin's
  call, since it is isolated.
- **24c (B3).** When a mention names an isolated worker, the annotation says
  so: "isolated: only you can send to it". The worker then asks you once
  instead of failing. This is cheaper than letting a relay through, which
  isolation forbids.
- **24d (B4).** A worker created by a worker joins its creator's groups
  unless the request names a group. Then the creator can always reach it.
- **24e (B5).** A dashboard send made by an automated browser (a recording,
  a route action) carries that session as its origin, and
  `kind=human` excludes it. First confirm from amux-gtm's recording that it
  drove those sends.
- **20c** (browser route loop), **23a**, **23b**, **23c**: unchanged and still
  open. 23c gets new evidence: MSG-103534 is 143 h old and duplicated.

Fixed in this window: the worker-rename-follows flake (e8737d64c, a retry to
